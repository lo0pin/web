CSS – Cascading Style Sheets

CSS steht für Cascading Style Sheets und ist die Sprache, mit der das Aussehen, die Anordnung und teilweise auch das Verhalten von HTML-Elementen beschrieben wird. HTML legt fest, was ein Element ist – beispielsweise eine Überschrift, ein Absatz, ein Bild, eine Navigation oder ein Formularfeld. CSS bestimmt anschließend, wie dieses Element dargestellt wird.

Dazu gehören weit mehr als Farben und Schriftgrößen. CSS kontrolliert unter anderem Abstände, Größen, Rahmen, Hintergründe, Positionen, responsive Layouts, Spalten, Raster, Animationen, Hover-Effekte und die Darstellung auf unterschiedlichen Bildschirmgrößen.

Modernes CSS ist damit keine bloße „Dekorationssprache“. Es ist ein umfangreiches Layoutsystem. Flexbox und Grid können komplexe Seitenstrukturen erzeugen, Media Queries passen Layouts an Bildschirmgrößen an, CSS-Variablen zentralisieren Designentscheidungen und Funktionen wie calc(), min(), max() oder clamp() ermöglichen dynamische Größenberechnungen.

Eine hilfreiche Denkweise lautet: HTML beschreibt die Bedeutung und Struktur – CSS beschreibt die Darstellung. Wenn du für ein rein optisches Problem plötzlich zusätzliche bedeutungslose <div>-Elemente brauchst, lohnt es sich oft, zuerst zu prüfen, ob CSS das Problem nicht eleganter lösen kann.

CSS einbinden

Bevor CSS etwas gestalten kann, muss der Browser wissen, welches Stylesheet zu einer HTML-Seite gehört. Dafür gibt es drei grundlegende Möglichkeiten.

Externes Stylesheet

Für echte Webseiten ist dies normalerweise die beste Variante. Das CSS befindet sich in einer eigenen Datei. 

<link rel="stylesheet" href="assets/css/main.css">

Diese Zeile gehört normalerweise in den <head> der HTML-Datei.

Vorteil: Ein einziges Stylesheet kann von vielen HTML-Seiten gemeinsam verwendet werden.

CSS direkt im HTML-Dokument

<style>
  body {
    background: #f7f7f7;
  }
</style>

Das funktioniert, eignet sich aber eher für kleine Experimente, einzelne Spezialseiten oder Prototypen.

Inline-CSS

<p style="color: red;">
  Dieser Text ist rot.
</p>

Inline-CSS hat eine hohe Priorität und verteilt Gestaltung direkt über das HTML. Das wird bei größeren Seiten sehr schnell unübersichtlich.

Für normale Webseiten: möglichst vermeiden.

Grundsyntax

Eine CSS-Regel

.card {
  background: white;
  border: 1px solid #ddd;
  padding: 1rem;
}

Eine CSS-Regel besteht grundsätzlich aus:

  • Selektor: Welches Element soll angesprochen werden?
  • Eigenschaft: Was soll verändert werden?
  • Wert: Welchen Wert erhält die Eigenschaft?

Im Beispiel ist .card der Selektor, background eine Eigenschaft und white ihr Wert.

Mehrere Deklarationen

.card {
  padding: 1rem;
  margin: 1rem 0;
  border-radius: 16px;
  background: #ffffff;
}

Jede Deklaration wird normalerweise mit einem Semikolon beendet. Beim letzten Eintrag ist das Semikolon technisch oft optional, sollte aber trotzdem gesetzt werden.

Kommentare

/* Navigation */

.top-nav {
  display: flex;
}

/*
  Kommentare können
  auch mehrere Zeilen
  umfassen.
*/

Kommentare helfen dabei, große Stylesheets zu gliedern.

Kommentare sollen erklären, warum etwas ungewöhnlich gelöst wurde. Jede offensichtliche Zeile mit einem kleinen Roman zu versehen, verschiebt das Problem nur von CSS zu Literaturkritik.

Leerraum ist weitgehend bedeutungslos

.card{padding:1rem;background:white;}

Funktioniert genauso wie: 

.card {
  padding: 1rem;
  background: white;
}

Die zweite Variante ist für Menschen allerdings wesentlich angenehmer.

Selektoren

Selektoren bestimmen, welche HTML-Elemente eine CSS-Regel erhalten. Wer Selektoren versteht, versteht einen erheblichen Teil von CSS.

Elementselektor

p {
  line-height: 1.6;
}

Wählt alle <p>-Elemente aus.

Klassenselektor

.card {
  background: white;
}

Wählt alle Elemente mit: 

class="card"

Klassen sind der wichtigste allgemeine Mechanismus für CSS-Styling.

ID-Selektor

#top {
  scroll-margin-top: 2rem;
}

Wählt das Element mit: 

id="top"

IDs sollen innerhalb einer Seite eindeutig sein.

Für normales Styling sind Klassen meist angenehmer. IDs erzeugen relativ hohe Spezifität.

Universalselektor

* {
  box-sizing: border-box;
}

* bedeutet: alle Elemente.

Mehrere Selektoren zusammenfassen

h1,
h2,
h3 {
  line-height: 1.25;
}

Alle aufgelisteten Selektoren erhalten dieselben Regeln.

Mehrere Klassen gleichzeitig

.card.warning {
  border-color: orange;
}

Das trifft nur Elemente, die beide Klassen besitzen: 

<div class="card warning">...</div>

Zwischen den Klassen steht dabei kein Leerzeichen.

Kombinatoren – Beziehungen zwischen Elementen

Selektoren können nicht nur einzelne Elemente ansprechen, sondern auch Beziehungen innerhalb der HTML-Struktur.

Nachfahrenselektor – Leerzeichen

.card p {
  margin-bottom: 1rem;
}

Wählt alle Absätze, die sich irgendwo innerhalb eines Elements mit class="card" befinden.

Direktes Kind – >

.card > p {
  margin-bottom: 1rem;
}

Wählt nur Absätze, die unmittelbare Kinder von .card sind.

Direkter Nachbar – +

h2 + p {
  margin-top: 0;
}

Wählt einen Absatz nur dann, wenn er unmittelbar auf ein <h2> folgt.

Spätere Geschwister – ~

h2 ~ p {
  color: var(--muted);
}

Wählt alle später folgenden Geschwister-Absätze desselben Elternelements.

Attributselektoren

HTML-Attribute können ebenfalls zur Auswahl von Elementen verwendet werden. Das ist besonders bei Formularen, Datenattributen und dynamisch gerenderten Elementen nützlich.

Attribut vorhanden

[disabled] {
  opacity: 0.5;
}

Wählt alle Elemente mit einem disabled-Attribut.

Exakter Attributwert

input[type="email"] {
  border-color: steelblue;
}

Eigene data-Attribute

[data-news-mode="latest"] {
  margin-top: 1rem;
}

Damit können auch Elemente angesprochen werden, die JavaScript über data-*-Attribute konfiguriert.

Weitere Attributvergleiche

[href^="https://"] { }
[href$=".pdf"] { }
[class*="news"] { }
  • ^= → beginnt mit
  • $= → endet mit
  • *= → enthält

Pseudoklassen

Pseudoklassen beschreiben einen bestimmten Zustand oder eine strukturelle Eigenschaft eines Elements. Sie werden mit einem einzelnen Doppelpunkt geschrieben.

:hover

a:hover {
  color: #000;
}

Wird aktiv, wenn sich der Mauszeiger über dem Element befindet.

:focus und :focus-visible

a:focus-visible {
  outline: 2px solid #0b5fff;
  outline-offset: 3px;
}

:focus-visible eignet sich besonders für Tastaturnavigation, weil der Fokusrahmen dort erscheint, wo er tatsächlich benötigt wird.

:active

button:active {
  transform: translateY(1px);
}

Gilt während eines aktiven Klicks beziehungsweise einer Aktivierung.

:first-child und :last-child

.card p:first-child {
  margin-top: 0;
}

.card p:last-child {
  margin-bottom: 0;
}

:nth-child()

li:nth-child(2) {
  font-weight: bold;
}

tr:nth-child(even) {
  background: rgba(0, 0, 0, 0.03);
}

Ermöglicht die Auswahl anhand der Position eines Elements.

:not()

.media-row:not(.compact) {
  gap: 2rem;
}

Wählt Elemente aus, die den angegebenen Selektor nicht erfüllen.

:is()

.news-body :is(h2, h3, h4) {
  line-height: 1.3;
}

Fasst mehrere mögliche Selektoren kompakt zusammen.

:where()

:where(.news-body, .news-teaser) p {
  line-height: 1.7;
}

Ähnelt :is(), besitzt aber selbst keine zusätzliche Spezifität. Das kann bei großen Stylesheets ausgesprochen praktisch sein.

:has()

.media-row:has(> .media:only-child) {
  grid-template-columns: 1fr;
}

Mit :has() kann ein Element abhängig von seinen Kindern oder Nachfahren ausgewählt werden.

Das ist bemerkenswert mächtig: CSS kann damit gewissermaßen „nach unten schauen und daraus eine Entscheidung nach oben ableiten“.

Pseudoelemente

Pseudoelemente erzeugen keine echten HTML-Elemente, erlauben aber das Styling bestimmter Teile eines Elements oder zusätzlicher visueller Ebenen. Sie werden üblicherweise mit zwei Doppelpunkten geschrieben.

::before und ::after

.tile::before {
  content: "";
  position: absolute;
  inset: 0;
  background: rgba(0, 0, 0, 0.35);
}

Sehr nützlich für Overlays, Dekorationen oder zusätzliche Ebenen, ohne dafür bedeutungslose HTML-Elemente einzubauen.

content

.external-link::after {
  content: " ↗";
}

content wird hauptsächlich zusammen mit ::before und ::after verwendet.

::selection

::selection {
  background: #dbeafe;
}

Kontrolliert die Darstellung markierten Textes.

::placeholder

input::placeholder {
  color: var(--muted);
}

Die Kaskade – warum CSS „Cascading“ heißt

Mehrere CSS-Regeln können gleichzeitig auf dasselbe Element wirken. Der Browser muss deshalb entscheiden, welche Deklaration tatsächlich gewinnt. Genau dieser Entscheidungsprozess ist die Kaskade.

Spätere Regel gewinnt

p {
  color: blue;
}

p {
  color: red;
}

Bei gleicher Spezifität ist der Absatz rot, weil die zweite Regel später definiert wurde.

Aber nicht immer

.intro {
  color: blue;
}

p {
  color: red;
}

Ein <p class="intro"> bleibt blau, weil der Klassenselektor spezifischer ist als der Elementselektor.

!important

.card {
  color: red !important;
}

!important kann die normale Kaskade überstimmen.

Nicht als Standardwaffe verwenden. Ein Stylesheet voller !important ist häufig ein Zeichen dafür, dass die Spezifität außer Kontrolle geraten ist.

Spezifität

Die Spezifität beschreibt grob gesagt, wie präzise ein Selektor ein Element auswählt. Ein spezifischerer Selektor kann einen allgemeineren überschreiben, selbst wenn der allgemeinere später im Stylesheet steht.

Grobe Rangfolge

  1. Inline-Styles
  2. ID-Selektoren
  3. Klassen, Attribute und Pseudoklassen
  4. Elemente und Pseudoelemente
p { }                 /* gering */
.card { }             /* höher */
.card p { }           /* noch höher */
#content p { }        /* deutlich höher */

Spezifitätskrieg vermeiden

/* unnötig kompliziert */
main .content article.card p.hint {
  color: gray;
}

/* meistens ausreichend */
.hint {
  color: gray;
}

Je länger und spezifischer Selektoren werden, desto schwieriger lassen sie sich später überschreiben.

Vererbung

Manche CSS-Eigenschaften werden von Elternelementen automatisch an ihre Kinder weitergegeben. Andere nicht.

Typisch vererbte Eigenschaften

body {
  color: #1f2328;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}

Textfarbe und Schrift werden normalerweise an untergeordnete Elemente weitergegeben.

Typisch nicht vererbte Eigenschaften

  • margin
  • padding
  • border
  • width
  • height
  • background

Vererbung erzwingen

button {
  font: inherit;
  color: inherit;
}

inherit übernimmt ausdrücklich den Wert des Elternelements.

Weitere globale Werte

color: initial;
color: inherit;
color: unset;
color: revert;
  • initial → ursprünglicher CSS-Standardwert
  • inherit → Wert des Elternobjekts
  • unset → je nach Eigenschaft initial oder inherit
  • revert → zurück zur vorherigen Ebene der Kaskade

Das Boxmodell

Fast jedes HTML-Element lässt sich gedanklich als rechteckige Box betrachten. Diese Box besitzt mehrere Schichten.

Die vier Ebenen

  1. Content – eigentlicher Inhalt
  2. Padding – Innenabstand
  3. Border – Rahmen
  4. Margin – Außenabstand
.box {
  width: 300px;
  padding: 20px;
  border: 2px solid #ccc;
  margin: 20px;
}

Das klassische Problem

Ohne border-box bedeutet: 

width: 300px;
padding: 20px;
border: 2px solid;

tatsächliche Breite: 

300 + 40 + 4 = 344px

box-sizing: border-box

*,
*::before,
*::after {
  box-sizing: border-box;
}

Mit border-box sind Padding und Border bereits in der angegebenen Breite enthalten.

Eine der unspektakulärsten und zugleich nützlichsten Grundregeln eines Stylesheets.

Outline ist nicht Border

.button:focus-visible {
  outline: 3px solid blue;
}

Eine outline verändert die Größe des Elements nicht. Deshalb eignet sie sich hervorragend für Fokusmarkierungen.

Margin, Padding und Gap

Padding – Innenabstand

.card {
  padding: 1.25rem;
}

Padding erzeugt Abstand zwischen Inhalt und Rahmen beziehungsweise Hintergrund des Elements.

Margin – Außenabstand

.card {
  margin: 1rem 0;
}

Margin erzeugt Abstand zwischen einem Element und seiner Umgebung.

Shorthand-Schreibweise

margin: 1rem;

/* oben/unten | links/rechts */
margin: 1rem 2rem;

/* oben | links/rechts | unten */
margin: 1rem 2rem 3rem;

/* oben | rechts | unten | links */
margin: 1rem 2rem 3rem 4rem;

Bei vier Werten hilft die Uhr: oben → rechts → unten → links.

Einzelne Seiten

margin-top: 1rem;
margin-right: 2rem;
margin-bottom: 1rem;
margin-left: 2rem;

gap

.tile-grid {
  display: grid;
  gap: 1rem;
}

Für Flexbox und Grid ist gap meist eleganter als Margins auf jedem einzelnen Kind.

Margin Collapsing

Vertikale Margins normaler Blockelemente können miteinander kollabieren. Zwei Margins von jeweils 20px ergeben daher nicht zwingend 40px. 

h2 {
  margin-bottom: 20px;
}

p {
  margin-top: 20px;
}

Zwischen den Elementen können effektiv nur 20px liegen.

Wenn Abstände scheinbar mathematische Gesetze missachten, hat CSS häufig gerade Margin Collapsing entdeckt.

Breite und Höhe

width und height

.box {
  width: 300px;
  height: 200px;
}

Feste Größen sind manchmal sinnvoll, bei responsiven Layouts aber häufig zu starr.

max-width

.content {
  width: 100%;
  max-width: 980px;
  margin: 0 auto;
}

Sehr typisches Muster: Der Inhalt darf kleiner werden, aber nicht über 980px hinauswachsen.

min-width und min-height

.hero {
  min-height: 160px;
}

Das Element darf größer werden, unterschreitet aber nicht die Mindestgröße.

auto

img {
  width: 100%;
  height: auto;
}

auto überlässt die passende Größe dem Browser beziehungsweise dem intrinsischen Seitenverhältnis des Inhalts.

aspect-ratio

.tile {
  aspect-ratio: 16 / 10;
}

Hält ein bestimmtes Seitenverhältnis aufrecht.

CSS-Einheiten

px

border: 1px solid #ddd;

Pixel eignen sich gut für sehr kleine, präzise Werte wie Rahmen. Sie sind jedoch nicht immer die beste Wahl für ganze Layoutsysteme.

rem

.card {
  padding: 1.25rem;
}

rem bezieht sich auf die Schriftgröße des Root-Elements <html>.

Bei der üblichen Standardschriftgröße gilt ungefähr: 

1rem = 16px
2rem = 32px
0.5rem = 8px

em

.button {
  padding: 0.6em 1em;
}

em orientiert sich stärker am jeweiligen lokalen Schriftgrößenkontext.

Prozentwerte

.child {
  width: 50%;
}

Prozentwerte beziehen sich je nach Eigenschaft auf einen übergeordneten Kontext.

vw und vh

.hero {
  min-height: 60vh;
}
  • 1vw = 1 % der Viewportbreite
  • 1vh = 1 % der Viewporthöhe

Moderne Viewport-Einheiten

.fullscreen {
  min-height: 100dvh;
}
  • dvh → dynamische Viewporthöhe
  • svh → kleine Viewporthöhe
  • lvh → große Viewporthöhe

Diese Einheiten sind insbesondere auf Mobilgeräten relevant, deren Browserleisten die sichtbare Höhe verändern können.

ch

.article-text {
  max-width: 70ch;
}

ch basiert ungefähr auf der Breite eines Zeichens. Dadurch eignet sich die Einheit hervorragend zur Begrenzung langer Textzeilen.

fr

.grid {
  grid-template-columns: 1fr 2fr;
}

fr bezeichnet einen Anteil des verfügbaren Platzes in CSS Grid.

Nützliche CSS-Funktionen

calc()

.page {
  width: calc(100% - 40px);
}

Ermöglicht Berechnungen mit unterschiedlichen Einheiten.

min()

.page {
  width: min(100% - 40px, 920px);
}

Verwendet den kleineren der angegebenen Werte.

max()

.box {
  width: max(300px, 50%);
}

Verwendet den größeren Wert.

clamp()

h1 {
  font-size: clamp(2rem, 5vw, 4rem);
}

Bedeutet:

  • mindestens 2rem
  • idealerweise 5vw
  • höchstens 4rem

Besonders nützlich für fließend responsive Typografie.

Text und Typografie

Schriftfamilie

body {
  font-family:
    system-ui,
    -apple-system,
    BlinkMacSystemFont,
    "Segoe UI",
    Roboto,
    Arial,
    sans-serif;
}

Mehrere Schriftarten bilden einen sogenannten Font Stack. Ist die erste nicht verfügbar, versucht der Browser die nächste.

Schriftgröße

body {
  font-size: 1rem;
}

h1 {
  font-size: 2rem;
}

Schriftgewicht

.title {
  font-weight: 700;
}

Übliche Werte:

  • 400 → normal
  • 500 → medium
  • 600 → semi-bold
  • 700 → bold

Zeilenhöhe

body {
  line-height: 1.6;
}

Ein einheitenloser Wert ist häufig sinnvoll, weil er sich automatisch mit der Schriftgröße skaliert.

Textausrichtung

.center {
  text-align: center;
}

.right {
  text-align: right;
}

Buchstabenabstand

.label {
  letter-spacing: 0.04em;
}

Wortabstand

.text {
  word-spacing: 0.1em;
}

Textumwandlung

.label {
  text-transform: uppercase;
}

Weitere Werte: lowercase, capitalize, none.

Unterstreichungen

a {
  text-decoration: underline;
  text-decoration-thickness: 1px;
  text-underline-offset: 3px;
}

Textschatten

.tile-label {
  text-shadow: 2px 2px 3px rgba(0, 0, 0, 0.6);
}

Reihenfolge: 

horizontal | vertikal | unschärfe | farbe

Lange Wörter umbrechen

.article {
  overflow-wrap: break-word;
}

Hilft bei langen URLs oder Zeichenketten, die sonst das Layout sprengen könnten.

Text nicht umbrechen

.label {
  white-space: nowrap;
}

Text mit … abschneiden

.title {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}

Farben

Farbnamen

color: red;
background: white;

Gut zum Experimentieren, für ein konsistentes Design sind Hex-, RGB- oder CSS-Variablen meist besser.

Hexadezimalfarben

color: #1f2328;
background: #ffffff;

Kurzform ist ebenfalls möglich: 

#fff
#000
#abc

RGB und Transparenz

background: rgb(255, 255, 255);

background: rgba(0, 0, 0, 0.35);

Beim klassischen rgba() bestimmt der letzte Wert die Deckkraft:

  • 0 → unsichtbar
  • 0.5 → halbtransparent
  • 1 → vollständig deckend

currentColor

a {
  color: #24556b;
  text-decoration-color: currentColor;
}

currentColor entspricht automatisch dem aktuellen Wert der Eigenschaft color.

Hintergründe

Hintergrundfarbe

.card {
  background-color: #ffffff;
}

Die Kurzform lautet schlicht: 

background: #ffffff;

Hintergrundbild

.hero {
  background-image: url("../img/photo.jpg");
}

Bildposition

.hero {
  background-position: center;
}

Möglich sind beispielsweise: center, top, bottom, left, right.

Hintergrundgröße

.hero {
  background-size: cover;
}
  • cover → Fläche vollständig ausfüllen, Beschneidung möglich
  • contain → gesamtes Bild sichtbar, freie Flächen möglich

Hintergrundwiederholung

.hero {
  background-repeat: no-repeat;
}

Kurzschreibweise

.hero {
  background:
    url("../img/photo.jpg")
    center / cover
    no-repeat;
}

Linearer Verlauf

.hero {
  background:
    linear-gradient(
      135deg,
      #ffffff,
      #e5e7eb
    );
}

Bild mit Overlay

.hero {
  background:
    linear-gradient(
      rgba(0, 0, 0, 0.35),
      rgba(0, 0, 0, 0.35)
    ),
    url("../img/photo.jpg")
    center / cover no-repeat;
}

Damit kann ein Bild direkt abgedunkelt werden, ohne zusätzliches HTML.

Rahmen, Rundungen und Schatten

Border

.card {
  border: 1px solid #e5e7eb;
}

Reihenfolge: 

dicke | linienart | farbe

Einzelne Rahmen

.header {
  border-bottom: 1px solid #ddd;
}

Border Radius

.card {
  border-radius: 16px;
}

Vollständig runde Elemente: 

.avatar {
  border-radius: 50%;
}

Box Shadow

.card {
  box-shadow:
    0 8px 24px rgba(0, 0, 0, 0.08);
}

Reihenfolge: 

x | y | unschärfe | ausbreitung | farbe

Schatten sehen meist besser aus, wenn man sie beinahe übersieht. Wenn die Card über der Seite schwebt wie ein außer Kontrolle geratenes UFO, war es vermutlich etwas zu viel.

Die Eigenschaft display

display: block

.box {
  display: block;
}

Blockelemente beginnen normalerweise in einer neuen Zeile und nehmen standardmäßig die verfügbare Breite ein.

display: inline

.label {
  display: inline;
}

Inline-Elemente befinden sich im normalen Textfluss. Klassisches Beispiel: <span>.

display: inline-block

.badge {
  display: inline-block;
  padding: 0.25rem 0.5rem;
}

Bleibt im Inline-Fluss, kann aber wie eine Box dimensioniert werden.

display: none

.hidden {
  display: none;
}

Das Element wird vollständig aus dem Layout entfernt.

visibility: hidden

.hidden {
  visibility: hidden;
}

Das Element wird unsichtbar, behält aber seinen Platz im Layout.

opacity

.faded {
  opacity: 0.5;
}

Das Element bleibt vorhanden, wird aber transparent.

Overflow – wenn Inhalt nicht hineinpasst

overflow: hidden

.tile {
  overflow: hidden;
}

Alles außerhalb der Box wird abgeschnitten. Besonders praktisch bei gezoomten Bildern.

overflow: auto

pre {
  overflow-x: auto;
}

Der Browser zeigt nur dann Scrollleisten, wenn sie tatsächlich notwendig sind.

overflow: scroll

.box {
  overflow: scroll;
}

Erzwingt einen scrollbaren Bereich.

Positionierung

position: static

Standardwert. Das Element bleibt im normalen Dokumentfluss.

position: relative

.tile {
  position: relative;
}

Das Element bleibt grundsätzlich im normalen Layout, erzeugt aber unter anderem einen Bezugspunkt für absolut positionierte Kinder.

position: absolute

.tile {
  position: relative;
}

.tile-label {
  position: absolute;
  left: 0;
  right: 0;
  bottom: 0;
}

Das Label wird relativ zum nächsten geeigneten positionierten Vorfahren platziert.

position: fixed

.background {
  position: fixed;
  inset: 0;
}

Das Element wird relativ zum Viewport positioniert und bleibt beim Scrollen an derselben Stelle.

position: sticky

.navigation {
  position: sticky;
  top: 0;
}

Das Element verhält sich zunächst normal und bleibt beim Erreichen der angegebenen Position „kleben“.

inset

.overlay {
  position: absolute;
  inset: 0;
}

Entspricht: 

top: 0;
right: 0;
bottom: 0;
left: 0;

Ebenen und z-index

Grundprinzip

.background {
  z-index: -1;
}

.overlay {
  z-index: 2;
}

.dialog {
  z-index: 10;
}

Größere Werte liegen grundsätzlich über kleineren Werten – allerdings nur innerhalb des jeweiligen Stacking Context.

Warum z-index: 999999 nicht immer hilft

Eigenschaften wie unter anderem position, transform, opacity oder bestimmte Layoutsituationen können neue Stacking Contexts erzeugen.

Wenn ein z-index scheinbar ignoriert wird, liegt das Problem häufig nicht an einer zu kleinen Zahl, sondern am falschen Stacking Context.

Flexbox

Flexbox eignet sich besonders für eindimensionale Layouts: Elemente sollen hauptsächlich in einer Zeile oder einer Spalte angeordnet werden.

Flexbox aktivieren

.header-inner {
  display: flex;
}

Die direkten Kinder werden dadurch zu Flex-Items.

Hauptrichtung

.container {
  display: flex;
  flex-direction: row;
}

Mögliche Werte:

  • row
  • row-reverse
  • column
  • column-reverse

justify-content

.header {
  display: flex;
  justify-content: space-between;
}

Kontrolliert die Verteilung entlang der Hauptachse.

  • flex-start
  • center
  • flex-end
  • space-between
  • space-around
  • space-evenly

align-items

.header {
  display: flex;
  align-items: center;
}

Kontrolliert die Ausrichtung auf der Querachse.

  • stretch
  • flex-start
  • center
  • flex-end
  • baseline

gap

.nav {
  display: flex;
  gap: 1rem;
}

Erzeugt gleichmäßige Abstände zwischen Flex-Items.

Umbrechen

.nav {
  display: flex;
  flex-wrap: wrap;
}

Elemente dürfen in eine neue Zeile springen, wenn der Platz nicht reicht.

flex-grow

.main {
  flex-grow: 1;
}

Bestimmt, wie stark ein Element zusätzlichen freien Platz erhält.

flex-shrink

.sidebar {
  flex-shrink: 0;
}

Verhindert hier, dass die Sidebar bei Platzmangel kleiner wird.

flex-basis

.item {
  flex-basis: 300px;
}

Definiert eine bevorzugte Ausgangsgröße.

Flex-Kurzform

.item {
  flex: 1 1 300px;
}

Entspricht grob: 

flex-grow: 1;
flex-shrink: 1;
flex-basis: 300px;

Ein einzelnes Element verschieben

.last-item {
  margin-left: auto;
}

Ein erstaunlich praktischer Trick: Das Element nimmt den freien Raum links von sich ein und wandert dadurch nach rechts.

Element individuell ausrichten

.special {
  align-self: flex-end;
}

Typischer Header

.header-inner {
  display: flex;
  justify-content: space-between;
  align-items: baseline;
  gap: 1rem;
}

.top-nav {
  display: flex;
  gap: 0.9rem;
  flex-wrap: wrap;
}

CSS Grid

CSS Grid eignet sich besonders für zweidimensionale Layouts, bei denen sowohl Spalten als auch Zeilen eine Rolle spielen.

Grid aktivieren

.grid {
  display: grid;
}

Drei gleiche Spalten

.tile-grid {
  display: grid;
  grid-template-columns:
    repeat(3, 1fr);
}

Robustere Variante

.tile-grid {
  display: grid;
  grid-template-columns:
    repeat(3, minmax(0, 1fr));
}

minmax(0, 1fr) verhindert einige typische Overflow-Probleme durch zu breite Inhalte.

Unterschiedliche Spaltenbreiten

.layout {
  display: grid;
  grid-template-columns:
    2fr 1fr;
}

Die erste Spalte erhält doppelt so viel freien Platz wie die zweite.

Feste und flexible Spalte

.layout {
  display: grid;
  grid-template-columns:
    250px 1fr;
}

Abstände

.grid {
  gap: 1rem;
}

Alternativ: 

row-gap: 1rem;
column-gap: 2rem;

Element über mehrere Spalten

.wide {
  grid-column: span 2;
}

Explizite Linien

.wide {
  grid-column: 1 / 3;
}

Das Element beginnt an Grid-Linie 1 und endet an Grid-Linie 3.

Automatisch responsive Spalten

.grid {
  display: grid;
  grid-template-columns:
    repeat(
      auto-fit,
      minmax(240px, 1fr)
    );
  gap: 1rem;
}

Der Browser erzeugt automatisch so viele Spalten, wie sinnvoll Platz haben.

Dieses Muster kann manche Media Queries vollständig ersetzen.

auto-fit und auto-fill

Beide erzeugen automatisch Spalten.

  • auto-fit lässt ungenutzte Spalten kollabieren und vorhandene Inhalte wachsen.
  • auto-fill reserviert mögliche Spaltenplätze eher weiter.

Zentrieren mit Grid

.hero {
  display: grid;
  place-items: center;
}

Zentriert den Inhalt horizontal und vertikal.

Grid oder Flexbox?

Eine brauchbare Faustregel:

  • Flexbox: eine Hauptdimension – Zeile oder Spalte.
  • Grid: Spalten und Zeilen gemeinsam.

Diese Grenze ist nicht absolut, aber ein sehr guter Ausgangspunkt.

Responsive Design

Responsive Design bedeutet, dass sich eine Webseite sinnvoll an unterschiedliche Bildschirmgrößen anpasst – nicht bloß, dass sie irgendwie auf einem Smartphone dargestellt werden kann.

Viewport-Meta-Tag

<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0"
>

Ohne diesen Eintrag funktionieren responsive Layouts auf Mobilgeräten häufig nicht wie erwartet.

Media Query

@media (max-width: 900px) {
  .tile-grid {
    grid-template-columns:
      repeat(2, minmax(0, 1fr));
  }
}

Mobile Ansicht

@media (max-width: 560px) {

  .header-inner {
    flex-direction: column;
    align-items: flex-start;
  }

  .tile-grid {
    grid-template-columns: 1fr;
  }

}

Mobile First

Eine Alternative besteht darin, zuerst die kleinste Darstellung zu definieren und größere Layouts anschließend mit min-width zu ergänzen. 

.grid {
  display: grid;
  grid-template-columns: 1fr;
}

@media (min-width: 700px) {
  .grid {
    grid-template-columns: 1fr 1fr;
  }
}

Breakpoints nicht nach Geräten benennen

Weniger sinnvoll: 

/* iPhone */
@media (max-width: 390px) { }

Besser: einen Breakpoint dort setzen, wo das Layout tatsächlich nicht mehr funktioniert.

Flüssige Breite

.page {
  width: min(
    calc(100% - 40px),
    920px
  );

  margin: 0 auto;
}

Damit bleibt links und rechts Luft, während die maximale Inhaltsbreite begrenzt wird.

Responsive Schriftgröße

h1 {
  font-size:
    clamp(2rem, 5vw, 4rem);
}

Container Queries

.card-wrapper {
  container-type: inline-size;
}

@container (min-width: 500px) {
  .card-content {
    display: grid;
    grid-template-columns: 1fr 1fr;
  }
}

Container Queries orientieren sich nicht am gesamten Viewport, sondern an der Größe eines Containers.

Besonders interessant für wiederverwendbare Komponenten, die an verschiedenen Stellen unterschiedlich viel Platz bekommen.

Bilder und Medien

Responsive Bilder

img {
  max-width: 100%;
  height: auto;
  display: block;
}

Verhindert, dass Bilder breiter als ihr Container werden.

object-fit: cover

.tile-image {
  width: 100%;
  height: 100%;
  object-fit: cover;
}

Das Bild füllt die gesamte Fläche. Es wird nicht verzerrt, kann aber beschnitten werden.

object-fit: contain

.star-map {
  width: 100%;
  height: 380px;
  object-fit: contain;
}

Das vollständige Bild bleibt sichtbar. Dadurch können leere Flächen entstehen.

object-position

.portrait {
  object-fit: cover;
  object-position: center top;
}

Bestimmt, welcher Bildbereich bei einer Beschneidung bevorzugt sichtbar bleibt.

Seitenverhältnis

.image-box {
  aspect-ratio: 16 / 9;
  overflow: hidden;
}

Filter

.background-image {
  filter:
    grayscale(0.5)
    saturate(0.7)
    blur(3px);
}

Weitere Filter sind unter anderem:

  • brightness()
  • contrast()
  • sepia()
  • opacity()

Links und interaktive Zustände

Grundstil

a {
  color: var(--text);
  text-decoration: underline;
  text-underline-offset: 3px;
}

Hover

a:hover {
  text-decoration-color: currentColor;
}

Hover-Effekte geben visuelles Feedback, dass ein Element interaktiv ist.

Tastaturfokus

a:focus-visible {
  outline:
    2px solid rgba(11, 95, 255, 0.45);

  outline-offset: 3px;
}

Fokusmarkierungen niemals ersatzlos entfernen.

Klickbare Fläche vergrößern

.tile {
  display: block;
  padding: 1rem;
}

Gerade bei Navigation und Touch-Bedienung sollte nicht nur ein winziges Wort anklickbar sein.

Mauszeiger

.zoomable-image {
  cursor: zoom-in;
}

Weitere häufige Werte: pointer, default, grab, not-allowed.

Transformationen

Mit transform können Elemente verschoben, skaliert oder gedreht werden, ohne das normale Layout neu berechnen zu müssen.

Skalieren

.tile:hover img {
  transform: scale(1.06);
}

Verschieben

.label {
  transform: translateY(10px);
}

Drehen

.icon {
  transform: rotate(45deg);
}

Mehrere Transformationen

.element {
  transform:
    translateY(-4px)
    scale(1.02);
}

Die Reihenfolge der Transformationen kann das Ergebnis verändern.

Transitions – weiche Zustandswechsel

Grundprinzip

.tile-image {
  transition:
    transform 180ms ease;
}

.tile:hover .tile-image {
  transform: scale(1.06);
}

Statt sofort von Zustand A nach Zustand B zu springen, wird der Übergang animiert.

Mehrere Eigenschaften

.button {
  transition:
    background 150ms ease,
    transform 150ms ease,
    opacity 150ms ease;
}

Nicht einfach transition: all

/* bequem, aber oft unnötig */
transition: all 200ms ease;

/* gezielter */
transition:
  transform 200ms ease,
  opacity 200ms ease;

Es ist meist besser, bewusst festzulegen, welche Eigenschaften animiert werden.

Animationen mit @keyframes

Einfache Animation

@keyframes fade-in {

  from {
    opacity: 0;
  }

  to {
    opacity: 1;
  }

}

.card {
  animation:
    fade-in 300ms ease;
}

Mehrere Zwischenschritte

@keyframes pulse {

  0% {
    transform: scale(1);
  }

  50% {
    transform: scale(1.05);
  }

  100% {
    transform: scale(1);
  }

}

Animation konfigurieren

.element {
  animation-name: pulse;
  animation-duration: 1s;
  animation-timing-function: ease;
  animation-iteration-count: infinite;
}

Animationen sparsam einsetzen

Animationen sollten eine Funktion erfüllen:

  • Zustandsänderungen verdeutlichen
  • Orientierung erleichtern
  • Interaktivität bestätigen
  • Hierarchien verständlicher machen

Eine Website muss nicht beweisen, dass der Browser interpolieren kann.

CSS-Variablen / Custom Properties

CSS-Variablen ermöglichen es, Werte zentral zu definieren und anschließend im gesamten Stylesheet wiederzuverwenden.

Variablen definieren

:root {
  --background: #f5f0e1;
  --surface: #ffffff;
  --text: #171717;
  --muted: #666666;
  --border: #ddddda;
  --accent: #24556b;
  --radius: 16px;
}

:root entspricht auf einer normalen HTML-Seite im Wesentlichen dem <html>-Element, besitzt aber eine passende Spezifität für globale Variablen.

Variable verwenden

body {
  color: var(--text);
  background: var(--background);
}

.card {
  background: var(--surface);
  border: 1px solid var(--border);
}

Fallback-Wert

.box {
  color:
    var(--special-color, black);
}

Existiert --special-color nicht, wird black verwendet.

Lokale Variable

.warning {
  --card-color: #8a4b00;
  color: var(--card-color);
}

Variablen können auch nur innerhalb eines bestimmten Bereichs definiert werden.

Variablen berechnen

.media {
  border-radius:
    calc(var(--radius) - 4px);
}

Designsystem aufbauen

:root {
  --space-xs: 0.25rem;
  --space-sm: 0.5rem;
  --space-md: 1rem;
  --space-lg: 2rem;

  --radius-sm: 8px;
  --radius-md: 16px;

  --max-width: 920px;
}

Dadurch entstehen konsistente Abstände und Größen, statt überall zufällige Einzelwerte zu verteilen.

Formulare gestalten

Grundstil für Eingabefelder

input,
textarea,
select {
  width: 100%;
  font: inherit;
  color: inherit;

  padding: 0.7rem 0.8rem;

  border:
    1px solid var(--border);

  border-radius: 8px;

  background: var(--surface);
}

Fokus

input:focus-visible,
textarea:focus-visible,
select:focus-visible {
  outline:
    2px solid var(--accent);

  outline-offset: 2px;
}

Button

button {
  font: inherit;
  cursor: pointer;

  padding: 0.65rem 1rem;

  border:
    1px solid var(--border);

  border-radius: 8px;
}

Deaktivierter Zustand

button:disabled {
  opacity: 0.5;
  cursor: not-allowed;
}

Ungültige Eingabe

input:invalid {
  border-color: #b42318;
}

Browser können Formulare anhand ihrer HTML-Attribute wie required, type, min oder pattern validieren.

Tabellen gestalten

Grundlayout

table {
  width: 100%;
  border-collapse: collapse;
}

th,
td {
  padding: 0.6rem;
  border-bottom:
    1px solid var(--border);
}

Textausrichtung

th {
  text-align: left;
}

.number {
  text-align: right;
}

.center {
  text-align: center;
}

Spaltenbreiten

<colgroup>
  <col style="width: 30%;">
  <col style="width: 50%;">
  <col style="width: 20%;">
</colgroup>

Alternativ können Klassen oder :nth-child() verwendet werden. 

th:nth-child(1),
td:nth-child(1) {
  width: 30%;
}

Zebra-Streifen

tbody tr:nth-child(even) {
  background:
    rgba(0, 0, 0, 0.03);
}

Breite Tabellen mobil

<div class="table-wrapper">
  <table>
    ...
  </table>
</div>
.table-wrapper {
  overflow-x: auto;
}

Die Tabelle bleibt damit lesbar, statt das gesamte Seitenlayout in die Breite zu sprengen.

Accessibility und CSS

Fokus sichtbar lassen

a:focus-visible,
button:focus-visible {
  outline:
    2px solid var(--accent);

  outline-offset: 3px;
}

Niemals einfach: 

outline: none;

setzen, ohne einen brauchbaren Ersatz bereitzustellen.

Bewegung reduzieren

@media
(prefers-reduced-motion: reduce) {

  *,
  *::before,
  *::after {
    scroll-behavior: auto;
    animation-duration: 0.01ms;
    animation-iteration-count: 1;
  }

}

Nutzer können im Betriebssystem angeben, dass sie reduzierte Animationen bevorzugen.

Kontrast beachten

Sehr hellgrauer Text auf weißem Hintergrund mag ästhetisch zurückhaltend aussehen, kann aber schlicht unlesbar sein.

„Muted“ darf leiser sein. Es sollte aber nicht flüstern, bis niemand mehr versteht, was dort steht.

Nicht nur Farbe verwenden

Zustände sollten möglichst nicht ausschließlich durch Farbe kommuniziert werden.

Ein Fehlerfeld kann beispielsweise zusätzlich einen Rahmen, ein Symbol oder erklärenden Text erhalten.

Lesbare Zeilenlänge

.article {
  max-width: 70ch;
}

Sehr breite Textzeilen erschweren das Zurückfinden an den Beginn der nächsten Zeile.

CSS debuggen

CSS-Probleme lassen sich meistens systematisch lösen. Blind Werte zu verändern, bis das Ergebnis zufällig richtig aussieht, funktioniert zwar gelegentlich – erzeugt aber gerne den nächsten Fehler drei Bildschirmbreiten weiter.

DevTools verwenden

Mit den Browser-Entwicklertools kannst du:

  • Elemente auswählen
  • aktive CSS-Regeln sehen
  • überschriebene Regeln erkennen
  • Werte live verändern
  • Boxmodell untersuchen
  • Grid und Flexbox visualisieren
  • Responsive Bildschirmgrößen simulieren

Debug-Rahmen

* {
  outline:
    1px solid rgba(255, 0, 0, 0.2);
}

Vorübergehend ausgesprochen nützlich, um zu erkennen, welches Element tatsächlich welchen Raum einnimmt.

Regel wird durchgestrichen

Wenn eine Eigenschaft in den DevTools durchgestrichen ist, wurde sie normalerweise von einer anderen Regel überschrieben.

Prüfe:

  • Spezifität
  • Reihenfolge
  • Media Queries
  • Inline-CSS
  • !important

Regel erscheint überhaupt nicht

Dann liegt häufig eines dieser Probleme vor:

  • Selektor falsch geschrieben
  • Klasse fehlt im HTML
  • CSS-Datei nicht geladen
  • Pfad zum Stylesheet falsch
  • Syntaxfehler weiter oben im CSS

Element ist zu breit

Prüfe insbesondere:

  • width
  • min-width
  • padding
  • box-sizing
  • lange untrennbare Inhalte
  • Grid-/Flex-Minimumgrößen

Flex- oder Grid-Element läuft über

.item {
  min-width: 0;
}

Diese kleine Regel behebt überraschend viele Probleme, wenn lange Inhalte innerhalb von Flex- oder Grid-Items nicht schrumpfen wollen.

z-index funktioniert nicht

Prüfe:

  • Ist das Element positioniert?
  • Gibt es einen anderen Stacking Context?
  • Besitzt ein Elternelement transform?
  • Besitzt ein Elternelement opacity kleiner als 1?

Absolute Positionierung sitzt falsch

Meist fehlt beim gewünschten Elternobjekt: 

position: relative;

Hintergrundbild fehlt

Wichtig: Pfade innerhalb einer CSS-Datei werden relativ zur CSS-Datei interpretiert – nicht relativ zur HTML-Datei. 

background:
  url("../img/photo.jpg");

Ein Stylesheet sinnvoll organisieren

Bei kleinen Projekten funktioniert beinahe jede Ordnung. Sobald eine Website wächst, wird die Struktur des CSS selbst jedoch Teil der Wartbarkeit.

Mögliche Reihenfolge

/* 1. Reset / Basis */

/* 2. Variablen */

/* 3. Grundtypografie */

/* 4. Seitenlayout */

/* 5. Header / Navigation */

/* 6. Komponenten */

/* 7. News / Spezialbereiche */

/* 8. Utilities */

/* 9. Responsive Regeln */

Komponenten zusammenhalten

Statt sämtliche Hover-Regeln am Ende der Datei zu sammeln, kann es übersichtlicher sein, alle Regeln für eine Komponente beieinander zu lassen: 

.tile { }

.tile img { }

.tile::before { }

.tile:hover img { }

.tile:hover::before { }

.tile:focus-visible { }

Klassen semantisch benennen

Besser: 

.card-meta
.news-item
.tile-label
.site-header

Weniger hilfreich: 

.gray-text
.left-box
.big-font
.margin20

Klassen sollten möglichst beschreiben, was etwas ist, nicht nur, wie es momentan aussieht.

Magic Numbers reduzieren

Wenn überall unterschiedliche Werte auftreten: 

13px
17px
22px
27px
31px

entsteht schnell visuelles Rauschen. Ein kleines System aus wiederkehrenden Abständen ist meist besser. 

:root {
  --space-sm: 0.5rem;
  --space-md: 1rem;
  --space-lg: 2rem;
}

Logische CSS-Eigenschaften

Modernes CSS besitzt neben left, right, top und bottom auch sogenannte logische Eigenschaften. Sie orientieren sich an Schreibrichtung und Textfluss.

Media Queries jenseits der Bildschirmbreite

Dunkles Farbschema

@media
(prefers-color-scheme: dark) {

  :root {
    --background: #111;
    --surface: #1b1b1b;
    --text: #eee;
  }

}

Reduzierte Bewegung

@media
(prefers-reduced-motion: reduce) {

  html {
    scroll-behavior: auto;
  }

}

Hover-fähige Geräte

@media (hover: hover) {

  .tile:hover img {
    transform: scale(1.06);
  }

}

Damit lassen sich Effekte gezielt nur auf Geräten verwenden, die tatsächlich einen Hover-Zustand besitzen.

Eine kleine sinnvolle Basis

Ein vollständiges CSS-Framework ist für viele statische Webseiten unnötig. Einige wenige Grundregeln sind jedoch ausgesprochen hilfreich. 

*,
*::before,
*::after {
  box-sizing: border-box;
}

html {
  scroll-behavior: smooth;
}

body {
  margin: 0;

  font-family:
    system-ui,
    -apple-system,
    BlinkMacSystemFont,
    "Segoe UI",
    Roboto,
    Arial,
    sans-serif;

  line-height: 1.6;
}

img,
picture,
video {
  max-width: 100%;
  height: auto;
}

button,
input,
textarea,
select {
  font: inherit;
}

Praktische Regeln für echtes CSS

  • HTML beschreibt Struktur, CSS Darstellung. Versuche nicht, Layoutprobleme mit bedeutungslosen HTML-Konstruktionen zu lösen, wenn CSS dafür zuständig ist.
  • Nutze Klassen als primäres Styling-Werkzeug. IDs sind hervorragend für eindeutige Anker und JavaScript-Ziele, aber für normales Styling meist unnötig spezifisch.
  • Setze global box-sizing: border-box. Dadurch werden Größen wesentlich vorhersehbarer.
  • Vermeide feste Breiten für große Inhaltsbereiche. width: 100% kombiniert mit max-width ist meist wesentlich robuster.
  • Begrenze lange Textzeilen. Ein max-width von ungefähr 60ch bis 75ch ist für längeren Lesetext häufig angenehm.
  • Nutze rem großzügig. Für Typografie und Abstände ist die Einheit meist flexibler als eine Landschaft aus hart verdrahteten Pixelwerten.
  • Pixel sind trotzdem nicht verboten. Ein 1px-Rahmen ist völlig vernünftig. CSS ist kein Glaubenskrieg.
  • Nutze gap für Flex- und Grid-Abstände. Das ist meist sauberer als komplizierte Margin-Regeln auf den einzelnen Kindern.
  • Flexbox für Gruppen und Reihen, Grid für Raster und Flächen. Nicht absolut, aber eine ausgezeichnete Ausgangsregel.
  • Nutze den normalen Dokumentfluss, solange er funktioniert. Absolute Positionierung ist ein Werkzeug – kein Layoutsystem.
  • Verwende position: absolute gezielt. Overlays, Labels und Icons: ausgezeichnet. Ganze Seitenlayouts: meistens unnötiges Leiden.
  • Definiere beim Elternobjekt position: relative, wenn ein absolut positioniertes Kind innerhalb dieses Elements verankert werden soll.
  • Nutze CSS-Variablen für wiederkehrende Designwerte. Farben, Radien, Abstände und maximale Seitenbreiten sollten nicht zwanzigmal unabhängig voneinander festgelegt werden.
  • Vermeide Magic Numbers. Wenn ein Element nur funktioniert, weil irgendwo margin-left: 137px steht, ist meist noch nicht das eigentliche Layoutproblem gelöst.
  • Vermeide unnötig hohe Spezifität. Ein Selektor wie main .page .content article.card p.hint mag präzise wirken, macht spätere Änderungen aber unangenehm.
  • Benutze !important nur mit Grund. Wenn jede zweite Regel wichtig ist, ist offenbar keine mehr wichtig.
  • Gestalte Komponenten unabhängig. Eine .card sollte möglichst nicht davon abhängen, ob sie gerade das siebte Kind eines bestimmten Containers ist.
  • Teste unterschiedliche Inhaltslängen. Ein Layout, das nur mit exakt deinem Beispieltitel funktioniert, ist noch kein robustes Layout.
  • Teste schmale Bildschirme früh. Responsive Design erst am Ende „hineinzupatchen“ führt häufig zu unnötigen Sonderregeln.
  • Teste auch sehr breite Bildschirme. Nicht nur Mobilgeräte können Layouts entlarven. Ein Fließtext über 1900 Pixel Breite ist keine Großzügigkeit, sondern eine Zumutung.
  • Bilder brauchen meist max-width: 100%. Sonst können sie ihren Container überschreiten.
  • object-fit: cover und contain bewusst unterscheiden. Cover beschneidet, Contain bewahrt das gesamte Motiv.
  • Hover ist Ergänzung, nicht Voraussetzung. Touchscreens besitzen keinen klassischen dauerhaften Hover-Zustand.
  • Fokuszustände gehören zum Design. Tastaturbedienung ist kein exotischer Sonderfall.
  • Animationen sollen erklären, nicht unterhalten. Kleine Bewegungen können Zustände verständlich machen. Dauernd hüpfende Interface-Elemente dagegen erklären vor allem, dass jemand @keyframes entdeckt hat.
  • Bevorzuge für Animationen transform und opacity. Sie lassen sich meist effizienter animieren als große Layoutänderungen.
  • Berücksichtige prefers-reduced-motion. Nicht jeder möchte oder verträgt starke Bewegungseffekte.
  • Verwende DevTools ständig. CSS lässt sich im Browser hervorragend live untersuchen und verändern. Diese Werkzeuge nicht zu verwenden wäre freiwillige Archäologie.
  • Wenn etwas nicht funktioniert, ändere nicht sofort zehn Werte. Prüfe zuerst, welches Element tatsächlich betroffen ist und welche Regel gewinnt.
  • Kontrolliere die Kaskade. Durchgestrichene Eigenschaften in den DevTools verraten dir meist unmittelbar, warum eine Regel nicht sichtbar wird.
  • Schreibe CSS für den Zustand der Website von morgen. Ein wenig Struktur kostet heute Minuten und spart später Stunden.

Die wichtigsten mentalen Modelle

Wenn CSS unverständlich wirkt, hilft es meist mehr, das zugrunde liegende Modell zu verstehen, als eine weitere einzelne Eigenschaft auswendig zu lernen.

  1. Alles ist zunächst eine Box.
    Verstehe Content, Padding, Border und Margin.
  2. Elemente besitzen einen normalen Dokumentfluss.
    Versuche diesen zu nutzen, bevor du Elemente manuell positionierst.
  3. Elternelemente kontrollieren häufig das Layout ihrer Kinder.
    Bei Flexbox und Grid wird die entscheidende Regel meist auf den Container gesetzt, nicht auf jedes Kind.
  4. CSS ist eine Kaskade.
    Wenn zwei Regeln dasselbe verändern wollen, entscheiden Ursprung, Wichtigkeit, Spezifität und Reihenfolge.
  5. Größen müssen nicht immer fest sein.
    max-width, Prozentwerte, fr, minmax() und clamp() erzeugen robustere Layouts.
  6. Responsive Design bedeutet Anpassung, nicht Verkleinerung.
    Manchmal müssen Spalten verschwinden, Navigationen umbrechen, Bilder anders zugeschnitten oder Elemente neu angeordnet werden.
  7. Die einfachste funktionierende Regel ist meistens die beste.
    CSS wird selten besser, indem man auf ein Problem noch drei zusätzliche Ebenen an Selektoren und Positionskorrekturen legt.

CSS wirkt am Anfang manchmal willkürlich, ist es aber erstaunlich selten. Wenn etwas „unerklärlich“ passiert, steckt fast immer eines von wenigen Grundprinzipien dahinter: Boxmodell, Dokumentfluss, Kaskade, Spezifität, Größenberechnung, Flex/Grid oder Positionierung. Sobald man herausfindet, welches davon gerade die Fäden zieht, wird aus schwarzer Magie wieder Technik.
