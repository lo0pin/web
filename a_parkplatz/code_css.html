HTML – ausführliche Anleitung & Cheatsheet

HTML steht für HyperText Markup Language und ist die Auszeichnungssprache, mit der die Struktur einer Webseite beschrieben wird. HTML sagt dem Browser nicht primär, wie etwas aussehen soll, sondern was etwas ist: eine Überschrift, ein Absatz, ein Link, ein Bild, eine Navigation, ein Formularfeld, ein Artikel oder eine Tabelle.

Das Zusammenspiel moderner Webseiten lässt sich grob so zusammenfassen: HTML beschreibt die Struktur, CSS gestaltet die Darstellung und JavaScript steuert Verhalten und Logik.

HTML ist keine Programmiersprache im engeren Sinn. Es enthält keine Schleifen, Variablen oder Funktionen. HTML beschreibt Dokumente und deren semantische Struktur. Der Browser liest dieses Dokument ein und erzeugt daraus das DOM – Document Object Model, auf das anschließend CSS und JavaScript zugreifen können.

Eine robuste Webseite beginnt fast immer mit gut strukturiertem HTML. Wenn die Struktur stimmt, werden CSS und JavaScript deutlich einfacher.

Grundprinzip von HTML

HTML beschreibt Bedeutung

Ein HTML-Dokument besteht aus Elementen. Diese Elemente geben dem Browser und anderen Programmen Informationen über die Bedeutung des Inhalts. 

<h1>Meine Webseite</h1>

<p>
  Das ist ein normaler Absatz.
</p>

<a href="about.html">Über mich</a>

Der Browser erkennt dadurch:

  • <h1> = Hauptüberschrift
  • <p> = Absatz
  • <a> = Link

HTML, CSS und JavaScript

Die drei Kerntechnologien des Webs erfüllen unterschiedliche Aufgaben.

Technologie Aufgabe
HTML Struktur und Bedeutung
CSS Layout und Gestaltung
JavaScript Verhalten und Logik

Wenn du mit HTML versuchst, Abstände oder Farben zu erzeugen, oder mit CSS versuchst, Dokumentstruktur zu ersetzen, kämpfen die Technologien gegeneinander.

Vom HTML zum DOM

Der Browser liest das HTML ein und baut daraus einen Baum von Objekten: das Document Object Model. 

html
├── head
└── body
    ├── header
    ├── main
    │   ├── section
    │   └── article
    └── footer

JavaScript kann diese Elemente anschließend finden, verändern, hinzufügen oder entfernen.

Grundstruktur eines HTML-Dokuments

Minimales HTML5-Dokument

<!DOCTYPE html>
<html lang="de">

<head>
  <meta charset="UTF-8">
  <meta
    name="viewport"
    content="width=device-width, initial-scale=1.0"
  >

  <title>Meine Webseite</title>
</head>

<body>

  <h1>Hallo Welt</h1>

</body>

</html>

Das ist ein sinnvoller Ausgangspunkt für praktisch jede normale HTML-Datei.

<!DOCTYPE html>

Der DOCTYPE steht ganz am Anfang des Dokuments. 

<!DOCTYPE html>

Er signalisiert dem Browser, dass modernes HTML verwendet wird. Ohne DOCTYPE kann ein Browser in den sogenannten Quirks Mode wechseln und ältere Darstellungsregeln verwenden.

<html>

Das <html>-Element umschließt das gesamte Dokument. 

<html lang="de">
  ...
</html>

Mit lang="de" wird die Sprache des Dokuments angegeben. Das hilft unter anderem Screenreadern, Suchmaschinen und Übersetzungsfunktionen.

<head> und <body>

Das Dokument besteht im Wesentlichen aus zwei Bereichen. 

<head>
  Metadaten, CSS, Seitentitel ...
</head>

<body>
  Sichtbarer Seiteninhalt ...
</body>

Im <head> stehen Informationen über das Dokument. Im <body> steht der eigentliche Inhalt.

Elemente, Tags und Inhalte

Normales Element

<p>Hallo Welt</p>

Dieses Element besteht aus:

  • öffnendem Tag: <p>
  • Inhalt: Hallo Welt
  • schließendem Tag: </p>

Leere Elemente

Manche Elemente besitzen keinen Inhalt und benötigen daher keinen schließenden Tag. 

<img src="bild.jpg" alt="Beschreibung">

<br>

<hr>

<meta charset="UTF-8">

<input type="text">

Schreibweisen wie <br /> funktionieren ebenfalls, der Slash ist in HTML5 aber nicht erforderlich.

Groß- und Kleinschreibung

HTML-Tagnamen sind grundsätzlich nicht case-sensitive. 

<P>Text</P>

<p>Text</p>

Trotzdem sollte modernes HTML konsequent kleingeschrieben werden.

Einheitlichkeit spart später erstaunlich viel geistigen Kleinkrieg.

Attribute

Was Attribute sind

Attribute ergänzen ein HTML-Element um zusätzliche Informationen. 

<a
  href="about.html"
  class="button"
  title="Über mich"
>
  About
</a>

Hier besitzt das Element drei Attribute: href, class und title.

Typische Attribute

Attribut Bedeutung
class Zuordnung zu einer oder mehreren CSS-/JS-Klassen
id Eindeutige Kennung innerhalb der Seite
href Ziel eines Links
src Quelle einer Ressource
alt Alternativtext eines Bildes
title Zusätzliche Information
lang Sprache des Elements
hidden Element ausblenden

Boolean-Attribute

Einige Attribute benötigen keinen eigenen Wert. Ihre bloße Anwesenheit bedeutet bereits „aktiv“. 

<input type="checkbox" checked>

<input type="text" required>

<button disabled>
  Nicht verfügbar
</button>

<script src="main.js" defer></script>

Verschachtelung

Elemente korrekt verschachteln

HTML-Elemente können andere Elemente enthalten. Dabei sollte die Verschachtelung sauber geschlossen werden. 

<p>
  Das ist
  <strong>sehr wichtig</strong>.
</p>

Falsch:

<p>
  Das ist
  <strong>sehr wichtig.
</p>
</strong>

Browser versuchen fehlerhaftes HTML oft automatisch zu reparieren. Das ist hilfreich, sollte aber nicht als Programmiertechnik missverstanden werden.

Einrückung

<section>
  <h2>Astronomie</h2>

  <article>
    <h3>Der Mond</h3>
    <p>Unser natürlicher Satellit.</p>
  </article>
</section>

Die Einrückung verändert das Ergebnis im Browser normalerweise nicht, macht die Struktur für Menschen aber erheblich verständlicher.

Kommentare

HTML-Kommentare

<!-- Das ist ein Kommentar. -->

Kommentare werden im Browser nicht als sichtbarer Seiteninhalt dargestellt. 

<!-- Navigation -->
<nav>
  ...
</nav>

<!-- News werden hier per JavaScript geladen -->
<div data-news-mode="latest"></div>

Kommentare sind gut für Struktur und ungewöhnliche Entscheidungen. Sie sollten aber nicht jede offensichtlich verständliche HTML-Zeile paraphrasieren.

Code temporär deaktivieren

<!--
<a href="old-page.html">
  Alte Seite
</a>
-->

Für kurze Tests ist das praktisch. Große Mengen auskommentierten Alt-Codes gehören langfristig jedoch eher in Git als mitten ins Dokument.

Text und Überschriften

Überschriften h1 bis h6

<h1>Astronomie</h1>

<h2>Sonnensystem</h2>

<h3>Planeten</h3>

<h4>Innere Planeten</h4>

<h5>Erde</h5>

Überschriften erzeugen eine logische Dokumenthierarchie. Sie sollten aufgrund ihrer Bedeutung gewählt werden, nicht aufgrund der gewünschten Schriftgröße.

Die Größe einer Überschrift wird mit CSS geändert. HTML entscheidet über ihre hierarchische Bedeutung.

Das <h1>

Das <h1> bezeichnet üblicherweise die wichtigste Überschrift der Seite. 

<main>
  <h1>Der Mond</h1>

  <section>
    <h2>Entstehung</h2>
  </section>

  <section>
    <h2>Geologie</h2>
  </section>
</main>

Absätze mit <p>

<p>
  HTML beschreibt die Struktur eines Dokuments.
</p>

<p>
  CSS übernimmt dessen visuelle Gestaltung.
</p>

Inhaltlich getrennte Gedanken sollten auch als getrennte Absätze ausgezeichnet werden.

Zeilenumbruch <br>

<p>
  Musterstraße 10<br>
  8010 Graz<br>
  Österreich
</p>

<br> erzwingt einen Zeilenumbruch. Es sollte für echte Zeilenumbrüche verwendet werden, etwa bei Adressen oder Gedichten – nicht als Ersatz für CSS-Abstände.

Thematische Trennung mit <hr>

<hr class="divider">

<hr> bedeutet semantisch eine thematische Zäsur. Dass daraus meist eine horizontale Linie wird, ist die Standarddarstellung.

Zitatblock <blockquote>

<blockquote>
  <p>
    Der Himmel ist nicht weniger tief,
    nur weil wir ihn vermessen.
  </p>
</blockquote>

Für längere Zitate ist <blockquote> semantisch besser geeignet als ein gewöhnlicher Absatz.

Wichtige Inline-Elemente

<strong>

Kennzeichnet starke inhaltliche Bedeutung oder Wichtigkeit. 

<p>
  Diese Spannung ist
  <strong>lebensgefährlich</strong>.
</p>

<em>

Kennzeichnet Betonung. 

<p>
  Das ist <em>wirklich</em> wichtig.
</p>

<b> und <i>

<b> und <i> können verwendet werden, wenn eine visuelle oder typografische Absetzung gemeint ist, aber keine stärkere semantische Bedeutung.

Für echte Wichtigkeit und Betonung sind <strong> und <em> meist die bessere Wahl.

Inline-Code mit <code>

<p>
  Die Datei heißt
  <code>posts.json</code>.
</p>

Für längere Codeblöcke kombiniert man <pre> und <code>.

<mark>

<p>
  Besonders relevant ist
  <mark>dieser Abschnitt</mark>.
</p>

<mark> kennzeichnet einen hervorgehobenen Textabschnitt, ähnlich einer Markierung mit Textmarker.

<small>

<small>
  Stand: August 2026
</small>

Geeignet für Nebenbemerkungen, Kleingedrucktes oder sekundäre Hinweise.

<sub> und <sup>

H<sub>2</sub>O

10<sup>6</sup>

E = mc<sup>2</sup>

<time>

<time datetime="2026-08-18">
  18. August 2026
</time>

Menschen sehen die ausgeschriebene Form, Maschinen erhalten über datetime einen eindeutig interpretierbaren Wert.

Link oder Button?

Eine der nützlichsten Regeln im Frontend:

  • Link: bringt Benutzer an einen anderen Ort.
  • Button: löst eine Aktion aus.
<a href="archive.html">
  Archiv öffnen
</a>

<button type="button">
  Filter zurücksetzen
</button>

Bilder mit <img>

Grundsyntax

<img
  src="assets/img/moon.jpg"
  alt="Zunehmender Mond über Graz"
>

src enthält die Bildquelle, alt eine textuelle Alternative.

Sinnvoller Alternativtext

Schlecht:

alt="Bild"

alt="Foto"

alt="moon.jpg"

Besser:

alt="Zunehmender Mond über dem Grazer Plabutsch"

Der Alternativtext sollte jene Information vermitteln, die das Bild im jeweiligen Kontext trägt.

Dekorative Bilder

Ist ein Bild rein dekorativ und vermittelt keinerlei zusätzliche Information, sollte ein leeres alt-Attribut verwendet werden. 

<img
  src="background-decoration.jpg"
  alt=""
>

Dadurch können Screenreader das Bild überspringen.

Lazy Loading

<img
  src="photo.jpg"
  alt="Segelboot in einer Bucht"
  loading="lazy"
  decoding="async"
>

loading="lazy" erlaubt dem Browser, weiter unten liegende Bilder erst bei Bedarf zu laden.

Für Bilder unmittelbar im sichtbaren oberen Seitenbereich ist Lazy Loading nicht unbedingt sinnvoll. Dort soll das Bild möglichst rasch verfügbar sein.

Breite und Höhe angeben

<img
  src="photo.jpg"
  alt="Berglandschaft"
  width="1600"
  height="900"
>

Sind die intrinsischen Bilddimensionen bekannt, kann der Browser schon vor dem Laden Platz reservieren. Das reduziert Layoutsprünge.

Bilder mit Bildunterschrift

<figure> und <figcaption>

<figure class="media">

  <img
    src="assets/img/moon.jpg"
    alt="Zunehmender Mond über dem Plabutsch"
  >

  <figcaption>
    Der zunehmende Mond über dem Grazer Plabutsch.
  </figcaption>

</figure>

<figure> gruppiert ein Medium mit zugehörigem Inhalt, <figcaption> liefert die sichtbare Beschriftung.

alt und figcaption erfüllen unterschiedliche Aufgaben. Sie müssen daher nicht identisch sein.

Klickbares Bild

<figure class="media">

  <a
    href="assets/img/moon-large.jpg"
    target="_blank"
    rel="noopener noreferrer"
  >

    <img
      src="assets/img/moon-small.jpg"
      alt="Detailaufnahme des Mondes"
    >

  </a>

  <figcaption>
    Anklicken für die größere Version.
  </figcaption>

</figure>

Keine Tabellen für Seitenlayout

Tabellen sind für echte tabellarische Daten gedacht. Für Seitenlayout verwendet man CSS Grid oder Flexbox.

Eine Tabelle, die nur deshalb existiert, damit links etwas links und rechts etwas rechts steht, ist ein Relikt aus einer dunkleren Epoche des Webdesigns.

Semantisches HTML

Semantische Elemente beschreiben die Funktion eines Bereichs. Dadurch wird die Seite für Browser, Screenreader, Suchmaschinen und nicht zuletzt für den eigenen zukünftigen Blick verständlicher.

<header>

Kopfbereich einer Seite oder eines Abschnitts. 

<header>
  <h1>Julian</h1>
</header>

<nav>

Bereich mit wesentlichen Navigationslinks. 

<nav aria-label="Hauptnavigation">
  <a href="index.html">Home</a>
  <a href="about.html">About</a>
</nav>

<main>

Enthält den eigentlichen Hauptinhalt einer Seite. 

<main>
  ...
</main>

Normalerweise gibt es pro Dokument genau einen sichtbaren Hauptbereich.

<section>

Thematischer Abschnitt eines Dokuments. 

<section>
  <h2>Entstehung des Mondes</h2>
  ...
</section>

Eine section sollte normalerweise eine Überschrift oder zumindest einen klar erkennbaren thematischen Zweck besitzen.

<article>

Eigenständig verständlicher Inhalt, beispielsweise:

  • News-Beitrag
  • Blogartikel
  • Forenbeitrag
  • Dokumentationseintrag
<article>
  <h2>Mein erster Meshtastic-Test</h2>
  <p>...</p>
</article>

<aside>

Inhalt, der nur ergänzend zum Hauptinhalt gehört. 

<aside>
  <h3>Weiterführende Links</h3>
  ...
</aside>

<footer>

<footer>
  <p>
    © 2026 Julian
  </p>
</footer>

Ein Footer kann für die gesamte Seite oder auch innerhalb einzelner Artikel verwendet werden.

  <header>
    <h1>Meine Webseite</h1>

      ...

  </header>


  <main>

    <section>
      <h2>Projekte</h2>

      <article>
        ...
      </article>

    </section>

  </main>


  <footer>
    ...
  </footer>

<div> und <span>

<div>

Ein <div> ist ein neutraler Block-Container. Es trägt selbst keine besondere semantische Bedeutung. 

<div class="tile-grid">

  <div class="tile">
    ...
  </div>

</div>

Es ist ideal für Layout oder Gruppierung, wenn kein passendes semantisches Element existiert.

<span>

<span> ist das Inline-Gegenstück zu <div>. 

<p>
  Temperatur:
  <span class="temperature">26 °C</span>
</p>

Keine div-Suppe

Technisch möglich:

<div class="header">
  <div class="navigation">
    ...
  </div>
</div>

Semantisch besser:

<header>
  <nav>
    ...
  </nav>
</header>

class und id

class

Klassen dürfen auf beliebig vielen Elementen verwendet werden. 

<article class="card">...</article>

<article class="card">...</article>

<article class="card">...</article>

Sie eignen sich deshalb hervorragend für wiederverwendbare CSS-Stile oder JavaScript-Gruppen.

Mehrere Klassen

<div class="media-row media-row--compact">
  ...
</div>

Mehrere Klassen werden innerhalb des Attributes durch Leerzeichen getrennt.

id

<section id="moon">
  ...
</section>

Eine ID sollte innerhalb eines Dokuments eindeutig sein.

Typische Verwendung:

  • Sprungmarken
  • JavaScript-Ziele
  • eindeutige Beziehungen zwischen Elementen

Faustregel

class = wiederverwendbar
id = eindeutig

Wenn du zehn Karten hast, bekommen alle zehn class="card". Sie bekommen nicht alle dieselbe ID.

Eigene Daten mit data-*

Eigene Attribute definieren

HTML erlaubt eigene Datenattribute, solange sie mit data- beginnen. 

<div
  data-news-topic="electronics"
  data-news-subtopic="mesh"
  data-news-mode="latest"
  data-news-limit="3"
></div>

Diese Attribute eignen sich besonders gut, um HTML-Konfiguration an JavaScript weiterzugeben.

Zugriff mit JavaScript

const element =
  document.querySelector("[data-news-mode]");

console.log(element.dataset.newsMode);
console.log(element.dataset.newsTopic);
console.log(element.dataset.newsLimit);

HTML: 

data-news-mode="latest"

wird in JavaScript zu: 

element.dataset.newsMode

Bindestriche werden bei dataset in CamelCase umgewandelt.

Dateipfade und URLs

Pfade gehören zu den häufigsten Ursachen für kaputte Bilder, Stylesheets und Links. Entscheidend ist immer: Von welchem Ausgangspunkt wird der Pfad aufgelöst?

Beispiel-Projektstruktur

web/
├── index.html
├── about.html
│
├── astronomy/
│   ├── home.html
│   └── moon.html
│
└── assets/
    ├── css/
    │   └── main.css
    ├── js/
    │   └── main.js
    └── img/
        └── moon.jpg

Relativer Pfad

Von index.html: 

<img
  src="assets/img/moon.jpg"
  alt="Mond"
>

Der Browser beginnt im Ordner der aktuellen HTML-Datei.

./ – aktueller Ordner

./assets/img/moon.jpg

entspricht meist:

assets/img/moon.jpg

../ – eine Ebene nach oben

Von astronomy/moon.html: 

../assets/img/moon.jpg

../ verlässt zunächst den Ordner astronomy.

Mehrere Ebenen nach oben

../       eine Ebene

../../     zwei Ebenen

../../../   drei Ebenen

Root-relativer Pfad

/web/assets/img/moon.jpg

Ein führender Slash beginnt am Root der Domain.

Bei: 

https://username.github.io/web/

führt:

/web/assets/img/moon.jpg

zu:

https://username.github.io/web/assets/img/moon.jpg

Wichtige GitHub-Pages-Falle

Bei einer Project Page unter: 

https://username.github.io/web/

würde:

/assets/img/moon.jpg

auf:

https://username.github.io/assets/img/moon.jpg

zeigen – also außerhalb des Repository-Pfades /web/.

Absolute URL

https://example.com/assets/img/moon.jpg

Eine vollständige URL enthält Protokoll, Domain und kompletten Pfad.

Relative Links sind portabler

Für eine statische Seite sind relative Pfade häufig sinnvoll, weil sie weniger stark an Repositoryname oder Domain gekoppelt sind. 

assets/img/photo.jpg

../assets/img/photo.jpg

Pfade in CSS funktionieren anders

Relative URLs in einer CSS-Datei beziehen sich auf den Ort der CSS-Datei.

Befindet sich CSS hier: 

assets/css/main.css

und das Bild hier:

assets/img/background.jpg

dann lautet der CSS-Pfad:

background-image:
  url("../img/background.jpg");

Groß- und Kleinschreibung

Moon.jpg
moon.jpg
moon.JPG

Diese Dateinamen können auf einem case-sensitiven Server drei unterschiedliche Dateien bezeichnen.

Was unter Windows lokal funktioniert, muss deshalb nicht zwingend auf GitHub Pages funktionieren.

Dateinamen

Ungünstig:

Mein tolles Mond Foto (FINAL).jpg

Besser:

moon-plabutsch-01.jpg

Sinnvoll sind:

  • Kleinbuchstaben
  • keine Leerzeichen
  • Bindestriche oder konsistente Unterstriche
  • klare Dateiendungen

Windows-Pfad ≠ URL

Falsch für eine Webseite:

C:\Users\Julian\Desktop\web\img\moon.jpg

Webpfad:

assets/img/moon.jpg

URLs verwenden /, nicht \.

HTML-Zeichen, Entities und Code darstellen

Warum Escaping nötig ist

Der Browser interpretiert spitze Klammern als HTML. Willst du einen HTML-Tag als Text anzeigen, musst du die Sonderzeichen maskieren.

Statt:

<p>Hallo</p>

steht im eigentlichen HTML-Code:

&lt;p&gt;Hallo&lt;/p&gt;

Wichtige HTML-Entities

Zeichen Entity
< &lt;
> &gt;
& &amp;
" &quot;
' &#39;
geschütztes Leerzeichen &nbsp;

Codeblock mit pre und code

<pre><code>
&lt;section class=&quot;card&quot;&gt;
  &lt;h2&gt;Titel&lt;/h2&gt;
&lt;/section&gt;
</code></pre>

<pre> bewahrt Einrückungen und Zeilenumbrüche, <code> kennzeichnet den Inhalt als Quellcode.

HTML-Escaping ≠ JSON-Escaping

Wird HTML oder Markdown innerhalb von JSON gespeichert, treffen unterschiedliche Escape-Regeln aufeinander. 

{
  "text": "class=\"card\"\nNeue Zeile"
}

In JSON:

  • \" maskiert Anführungszeichen.
  • \n repräsentiert einen Zeilenumbruch.

HTML-Entities wie &lt; lösen dagegen ein anderes Problem.

Barrierefreiheit / Accessibility

Zugängliches HTML ist keine exotische Zusatzfunktion. Viele Grundlagen entstehen automatisch, wenn die richtigen HTML-Elemente verwendet werden.

Semantik zuerst

Besser:

<button type="button">
  Menü öffnen
</button>

Statt:

<div onclick="openMenu()">
  Menü öffnen
</div>

Ein echter Button bringt Tastaturverhalten, Fokusierbarkeit und semantische Bedeutung bereits mit.

Alternative Bildtexte

<img
  src="weather-station.jpg"
  alt="Arduino-Wetterstation mit OLED-Display"
>

Informative Bilder benötigen einen sinnvollen Alternativtext.

Sprache angeben

<html lang="de">

Ändert sich die Sprache innerhalb eines Dokuments, kann sie auch lokal angegeben werden: 

<p lang="en">
  This paragraph is English.
</p>

Logische Überschriften

<h1>Astronomie</h1>

<h2>Sonnensystem</h2>

<h3>Erde</h3>

Screenreader können Überschriften als Navigationsstruktur verwenden.

ARIA sparsam verwenden

<nav aria-label="Hauptnavigation">
  ...
</nav>

ARIA kann zusätzliche semantische Informationen liefern. Es sollte aber nicht als Ersatz für korrektes HTML verwendet werden.

Die erste Regel von ARIA lautet sinngemäß: Wenn natives HTML das Problem bereits löst, verwende natives HTML.

Tastaturbedienbarkeit

Interaktive Elemente müssen mit der Tastatur erreichbar sein. Links, Buttons und Formularelemente bringen dies normalerweise bereits mit.

Deshalb sollte ein klickbares <div> nicht leichtfertig einen echten Button ersetzen.

Focus nicht zerstören

Elemente sollten beim Navigieren mit Tab sichtbar fokussiert bleiben.

Ein pauschales outline: none ist daher meist eine schlechte Idee. Wenn du den Browser-Fokus entfernst, musst du einen mindestens ebenso deutlichen eigenen Fokusstil bereitstellen.

Fehlersuche und Validierung

Browser Developer Tools

Die Entwicklertools des Browsers sind eines der wichtigsten Werkzeuge bei der Webentwicklung.

Besonders relevant:

  • Elements / Inspector: DOM und CSS untersuchen
  • Console: JavaScript-Fehler und Logs
  • Network: geladene Dateien und HTTP-Fehler
  • Sources: geladene HTML-, CSS- und JS-Dateien

404-Fehler

Ein 404 bedeutet: Die angeforderte Ressource wurde unter dieser URL nicht gefunden.

Bei kaputten Bildern oder Stylesheets solltest du deshalb im Network-Tab prüfen, welche URL der Browser tatsächlich angefordert hat.

Typische Pfadfehler

  • falscher Ordner
  • falsche Dateiendung
  • Groß-/Kleinschreibung stimmt nicht
  • ein ../ fehlt
  • führender Slash startet am falschen Root

HTML-Fehler können Folgefehler erzeugen

Ein vergessenes schließendes Element kann dazu führen, dass große Teile des nachfolgenden Dokuments anders im DOM landen, als der Quellcode zunächst vermuten lässt. 

<article>
  <p>Text

<article>
  ...
</article>

Deshalb lohnt es sich, bei mysteriösen Layoutfehlern auch die HTML-Struktur selbst zu prüfen.

Quelltext vs. DOM

Der Quelltext ist das HTML, das du geschrieben hast. Das DOM ist die Struktur, die der Browser daraus tatsächlich erzeugt hat.

Bei fehlerhaftem HTML können diese beiden Dinge voneinander abweichen, weil der Browser versucht, das Dokument zu reparieren.

Element direkt testen

Bei einem kaputten Bild kannst du dessen errechnete URL aus den Developer Tools kopieren und direkt in einem neuen Tab öffnen.

Nicht fünf Minuten den Pfad anstarren und auf ein Geständnis hoffen. Lass dir vom Browser zeigen, wo er tatsächlich gesucht hat.

Die wichtigsten mentalen Modelle

1. Erst Bedeutung, dann Aussehen

Frage zuerst: Was ist dieser Inhalt?

Erst danach: Wie soll er aussehen?

Wenn etwas eine Navigation ist, verwende <nav>. Wenn etwas ein Artikel ist, verwende <article>. Wenn etwas ein Button ist, verwende <button>.

2. HTML ist ein Baum

Fast jedes Element besitzt einen Elternknoten, Geschwisterelemente und möglicherweise eigene Kindknoten. 

main
└── article
    ├── h2
    ├── p
    └── figure
        ├── img
        └── figcaption

Dieses Baumdenken ist später für CSS-Selektoren und JavaScript enorm wichtig.

3. URLs sind Ortsbeschreibungen

Bei einem Pfadproblem ist die entscheidende Frage nicht: „Warum findet HTML mein Bild nicht?“

Sondern: „Von welcher URL startet der Browser und zu welcher URL führt dieser Pfad?“

4. Browser sind fehlertolerant

Browser versuchen kaputtes HTML zu reparieren. Deshalb führt schlechtes HTML nicht immer sofort zu einer Fehlermeldung.

„Der Browser zeigt etwas an“ ist nicht dasselbe wie „das HTML ist korrekt“.

5. HTML sollte auch ohne CSS Sinn ergeben

Ein gutes HTML-Dokument besitzt bereits ohne Gestaltung eine nachvollziehbare Struktur: Titel, Überschriften, Absätze, Listen, Links und Medien.

CSS macht daraus anschließend die visuelle Oberfläche.

6. Weniger Speziallösungen sind oft besser

Moderne HTML-Elemente können viele Dinge bereits ohne JavaScript:

  • <details> für aufklappbare Bereiche
  • <dialog> für Dialogfenster
  • Formularvalidierung über Input-Attribute
  • loading="lazy" für Bilder

Nutze native Browserfunktionen, bevor du dieselbe Funktion selbst nachbaust.

Praxisregeln – die wichtigsten Dinge zum Mitnehmen

  1. HTML ist für Struktur und Bedeutung zuständig. Gestaltung gehört überwiegend in CSS, Verhalten in JavaScript.
  2. Beginne jede normale Seite mit einem sauberen HTML5-Grundgerüst.
  3. Verwende semantische Elemente. header, nav, main, section, article und footer sind meist besser als eine unüberschaubare Masse neutraler div-Container.
  4. Strukturiere Überschriften logisch. Nutze h1 bis h6 nach Hierarchie, nicht nach gewünschter Schriftgröße.
  5. Nutze class für wiederverwendbare Gruppen und id für eindeutige Elemente.
  6. Gib informativen Bildern einen aussagekräftigen alt-Text.
  7. Dekorative Bilder bekommen alt="".
  8. Links navigieren, Buttons führen Aktionen aus.
  9. Formularfelder brauchen verständliche Labels.
  10. Verwende Tabellen nur für tabellarische Daten. Seitenlayout gehört in CSS Grid oder Flexbox.
  11. Behandle Pfade als URLs, nicht als abstrakte Dateinamen. Überlege immer, von welchem Dokument aus sie aufgelöst werden.
  12. Achte bei GitHub Pages auf den Repository-Pfad. Ein führendes / bedeutet Domain-Root, nicht automatisch Repository-Root.
  13. Achte exakt auf Groß- und Kleinschreibung. Besonders bei Dateinamen.
  14. Verwende kurze, vorhersehbare Dateinamen ohne Leerzeichen.
  15. Trenne HTML, CSS und JavaScript sauber. Das hält das Projekt verständlich und wartbar.
  16. Nutze data-*-Attribute, wenn HTML Informationen an JavaScript übergeben soll.
  17. Escape dynamischen oder fremden Text, bevor er als HTML eingefügt wird.
  18. Vermeide ungeprüftes innerHTML für externe oder vom Benutzer stammende Inhalte.
  19. Teste deine Seite über einen lokalen Webserver. Zum Beispiel: python -m http.server 8000.
  20. Verwende die Browser Developer Tools. Besonders Console, Elements und Network.
  21. Ein 404 ist fast immer eine sehr konkrete Aussage. Sieh dir an, welche URL tatsächlich angefordert wurde.
  22. Halte die Verschachtelung sauber und konsistent eingerückt.
  23. Vertraue nicht darauf, dass der Browser fehlerhaftes HTML schon irgendwie repariert.
  24. Nutze natives HTML, wenn es die gewünschte Funktion bereits bietet. Weniger JavaScript bedeutet häufig weniger Fehler, weniger Code und bessere Accessibility.
  25. Schreibe HTML auch für dein zukünftiges Ich. Lesbarer Code ist keine Zierde, sondern Wartungsinfrastruktur.

Was man wirklich beherrschen sollte

Man muss nicht jedes HTML-Element auswendig kennen. Entscheidend ist ein solides Verständnis der grundlegenden Mechanik: Dokumentstruktur, semantische Elemente, Verschachtelung, Attribute, Links, Pfade, Bilder, Formulare und die Trennung zwischen HTML, CSS und JavaScript.

Wer außerdem versteht, dass der Browser aus HTML einen DOM-Baum erzeugt, relative URLs immer einen Ausgangspunkt besitzen und semantisches HTML bereits einen beträchtlichen Teil von Accessibility und Wartbarkeit liefert, hat die wesentlichen Grundlagen nicht nur gelernt, sondern verstanden.

Der eigentliche Fortschritt beginnt dort, wo du beim Schreiben nicht mehr fragst: „Welchen Tag brauche ich dafür?“ – sondern: „Was ist dieser Inhalt semantisch, und welches HTML-Element beschreibt ihn am besten?“
