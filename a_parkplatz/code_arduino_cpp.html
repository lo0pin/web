Arduino & C++

Arduino ist eine Mikrocontroller-Plattform für eingebettete Systeme: Sensoren auslesen, LEDs und Motoren ansteuern, Displays betreiben, Messwerte speichern, Daten über UART, I²C oder SPI austauschen und physische Vorgänge mit Software verbinden.

Die häufig als „Arduino-Sprache“ bezeichnete Programmiersprache ist keine eigenständige Sprache. Arduino verwendet im Kern C++ und ergänzt dieses um ein Framework aus Funktionen, Bibliotheken und einer vereinfachten Projektstruktur. Ein Arduino-Sketch ist daher letztlich ein C++-Programm für einen Mikrocontroller.

Diese Übersicht behandelt sowohl die Arduino-spezifischen Funktionen als auch jene C++-Grundlagen, die für die Entwicklung eingebetteter Systeme besonders wichtig sind. Die Beispiele orientieren sich an klassischen Arduino-Boards wie Uno und Nano. Bei moderneren Boards wie ESP32, RP2040, Arduino Nano ESP32, Uno R4 oder verschiedenen ARM-Boards können sich Spannungen, Pin-Funktionen, ADC-Auflösung, PWM-Verhalten und verfügbare Bibliotheken unterscheiden.

Grundgedanke: Auf einem Mikrocontroller läuft normalerweise kein Betriebssystem, das sich um den Rest kümmert. Dein Programm ist sehr unmittelbar für die Hardware verantwortlich. Ein falsch gesetzter Pin ist daher nicht bloß ein Softwarefehler – er kann im ungünstigsten Fall auch elektrische Folgen haben.

Arduino und C++ verstehen

Arduino ist keine eigene Programmiersprache

Ein Arduino-Sketch wird als C++ übersetzt und anschließend für den jeweiligen Mikrocontroller kompiliert. 

int temperatur = 23;

void setup() {
    Serial.begin(9600);
}

void loop() {
    Serial.println(temperatur);
}

Variablen, Funktionen, Klassen, Operatoren, Arrays, Strukturen und Kontrollstrukturen stammen aus C++.

Was Arduino ergänzt

Arduino liefert unter anderem:

  • setup() und loop()
  • digitalWrite()
  • digitalRead()
  • analogRead()
  • analogWrite()
  • millis()
  • delay()
  • Serial
  • Bibliotheken für Hardware

Was beim Kompilieren passiert

  1. Der Sketch wird vorbereitet.
  2. C++-Quellcode wird kompiliert.
  3. Bibliotheken werden eingebunden.
  4. Maschinencode wird erzeugt.
  5. Das Programm wird auf den Mikrocontroller übertragen.

Der Mikrocontroller versteht am Ende nicht digitalWrite(), sondern ausschließlich Maschinenbefehle.

Embedded Programming

Arduino-Programmierung unterscheidet sich von klassischer PC-Programmierung vor allem durch beschränkte Ressourcen und den unmittelbaren Kontakt zur Hardware.

  • begrenzter RAM
  • begrenzter Flash-Speicher
  • begrenzte Rechenleistung
  • echte elektrische Ein- und Ausgänge
  • zeitkritische Abläufe
  • oft kein Betriebssystem

Aufbau eines Arduino-Sketches

Minimaler Sketch

void setup() {

}

void loop() {

}

Jeder klassische Arduino-Sketch enthält normalerweise diese beiden Funktionen.

setup()

void setup() {
    Serial.begin(9600);
    pinMode(LED_BUILTIN, OUTPUT);
}

setup() wird nach dem Start beziehungsweise Reset einmal aufgerufen.

Typische Aufgaben:

  • Pin-Modi setzen
  • serielle Schnittstelle starten
  • Sensoren initialisieren
  • Displays starten
  • Startwerte festlegen

loop()

void loop() {
    int wert = analogRead(A0);
    Serial.println(wert);
}

Nach setup() wird loop() permanent wiederholt.

Das Ende der Funktion bedeutet also keineswegs das Ende des Programms. Arduino ruft sie unmittelbar erneut auf.

Was vereinfacht dargestellt dahintersteckt

int main() {
    initialisiereHardware();

    setup();

    while (true) {
        loop();
    }
}

Der wirkliche Arduino-Core ist komplexer, aber dieses Modell erklärt sehr gut, warum loop() immer wieder ausgeführt wird.

Kommentare

// Einzeiliger Kommentar

/*
   Mehrzeiliger
   Kommentar
*/

Gute Kommentare erklären das Warum, nicht das ohnehin sichtbare Was. 

// schlecht:
counter++; // counter um eins erhöhen

// besser:
// Nach zehn gültigen Messungen Mittelwert bilden
counter++;

Grundlegende C++-Syntax

Semikolon

int temperatur = 23;
digitalWrite(13, HIGH);
Serial.println("Hallo");

Viele Anweisungen enden mit einem Semikolon.

Ein vergessenes Semikolon kann Fehlermeldungen an Stellen erzeugen, die mit dem eigentlichen Fehler scheinbar wenig zu tun haben. Der Compiler ist kein Hellseher.

Blöcke mit geschweiften Klammern

if (temperatur > 30) {
    Serial.println("Heiss");
}

{ und } markieren zusammengehörige Codeblöcke.

Groß- und Kleinschreibung

int sensorWert = 5;
int sensorwert = 8;

C++ unterscheidet Groß- und Kleinschreibung. Diese beiden Variablen sind daher verschieden. 

digitalWrite(13, HIGH); // korrekt
DigitalWrite(13, HIGH); // andere Bezeichnung → Fehler

Einrückung

if (wert > 500) {
    digitalWrite(ledPin, HIGH);
} else {
    digitalWrite(ledPin, LOW);
}

Einrückungen verändern die Bedeutung des C++-Codes nicht, wohl aber die Wahrscheinlichkeit, dass ein Mensch ihn noch versteht.

Variablen und Datentypen

Variablen speichern Daten im Arbeitsspeicher. Anders als in Python muss in C++ normalerweise angegeben werden, welchen Datentyp eine Variable besitzt.

bool

bool lichtAn = true;
bool fehler = false;

Speichert einen Wahrheitswert: true oder false.

char

char zeichen = 'A';

Speichert ein einzelnes Zeichen.

Einzelne Zeichen stehen in einfachen Anführungszeichen.

byte

byte helligkeit = 255;

Auf Arduino typischerweise ein vorzeichenloser 8-Bit-Wert von 0 bis 255.

int

int temperatur = 23;
int differenz = -5;

Ganzzahltyp. Seine Größe hängt von der Plattform ab. Auf klassischen AVR-Arduinos besitzt int typischerweise 16 Bit, auf vielen moderneren Mikrocontrollern 32 Bit.

unsigned int

unsigned int zaehler = 60000;

Ganzzahl ohne negatives Vorzeichen. Dadurch kann der positive Wertebereich größer sein.

long

long position = -150000L;

Ganzzahltyp für größere Werte.

unsigned long

unsigned long startzeit = 0;
unsigned long jetzt = millis();

Besonders wichtig für Zeitmessungen mit millis() und micros().

float

float temperatur = 21.75;

Gleitkommazahl für Werte mit Nachkommastellen.

Gleitkommaoperationen sind auf kleinen Mikrocontrollern häufig deutlich aufwendiger als Ganzzahlarithmetik.

double

double wert = 3.1415926;

Auf manchen Arduino-Plattformen besitzt double mehr Genauigkeit als float. Auf klassischen AVR-Arduinos sind beide hingegen gleich groß.

Explizite Integer-Typen

#include <stdint.h>

uint8_t a = 255;
int16_t b = -1200;
uint32_t c = 100000;

Typen wie uint8_t, int16_t oder uint32_t geben ihre Bitbreite ausdrücklich an und sind für hardware-nahe Programme besonders praktisch.

Variable deklarieren

int messwert;

Die Variable existiert, erhält hier aber noch keinen expliziten Startwert.

Variable initialisieren

int messwert = 0;

Die Variable wird erzeugt und erhält gleichzeitig einen definierten Wert.

Wert verändern

int wert = 10;

wert = 20;
wert = wert + 5;

Kurzschreibweisen

wert += 5;
wert -= 2;
wert *= 3;
wert /= 2;

wert++;
wert--;

wert++ erhöht den Wert um eins, wert-- vermindert ihn um eins.

Typumwandlung

float temperatur = 21.8;
int ganzzahl = (int)temperatur;

Ergebnis: 21.

Der Nachkommateil wird dabei nicht mathematisch gerundet, sondern abgeschnitten.

Integer-Division

int a = 5;
int b = 2;

float ergebnis = a / b;

Das Ergebnis ist zunächst 2, nicht 2.5, weil die Division mit Ganzzahlen erfolgt. 

float ergebnis = (float)a / b;

// ergibt 2.5

Überlauf

Jeder Integer-Typ besitzt einen begrenzten Wertebereich. Wird dieser überschritten, kann der Wert umspringen. 

uint8_t wert = 255;
wert++;

Serial.println(wert);

// Ergebnis: 0
Diese Eigenschaft ist kein exotischer Sonderfall. Zeitfunktionen wie millis() laufen ebenfalls irgendwann über.

Konstanten und Präprozessor

const

const int ledPin = 13;
const float grenzwert = 25.0;

Der Wert darf nach der Initialisierung nicht mehr verändert werden.

Für Pin-Nummern und feste Konfigurationswerte ist const meist die sauberste Lösung.

constexpr

constexpr int ledPin = 13;
constexpr unsigned long interval = 1000;

Modernes C++ ermöglicht mit constexpr, ausdrücklich Konstanten zu definieren, deren Wert bereits zur Übersetzungszeit feststeht.

#define

#define LED_PIN 13

Der C/C++-Präprozessor ersetzt LED_PIN vor dem Kompilieren durch 13.

Für einfache Konstanten sind const oder constexpr gewöhnlich sicherer und klarer als #define.

Bedingte Kompilierung

#define DEBUG

#ifdef DEBUG
    Serial.println("Debug-Ausgabe");
#endif

Damit können Teile des Programms nur unter bestimmten Bedingungen kompiliert werden.

Operatoren

Arithmetische Operatoren

a + b
a - b
a * b
a / b
a % b

% liefert den Rest einer Ganzzahldivision. 

int rest = 10 % 3;

// rest = 1

Vergleichsoperatoren

a == b
a != b
a > b
a < b
a >= b
a <= b

Das Ergebnis eines Vergleichs ist true oder false.

Zuweisung ist nicht Vergleich

wert = 10;      // Zuweisung

wert == 10      // Vergleich
= und == zu verwechseln ist ein Klassiker mit jahrzehntelanger Tradition. Man muss diese Tradition nicht fortführen.

Logische Operatoren

&&   // UND
||   // ODER
!    // NICHT
if (temperatur > 20 && temperatur < 30) {
    Serial.println("Temperatur im Bereich");
}

Bedingungen und Programmlogik

if

if (temperatur > 30) {
    digitalWrite(luefterPin, HIGH);
}

Der Block wird nur ausgeführt, wenn die Bedingung wahr ist.

if ... else

if (lichtwert < 300) {
    digitalWrite(ledPin, HIGH);
} else {
    digitalWrite(ledPin, LOW);
}

else if

if (temperatur >= 30) {
    Serial.println("heiss");
}
else if (temperatur >= 20) {
    Serial.println("warm");
}
else if (temperatur >= 10) {
    Serial.println("kuehl");
}
else {
    Serial.println("kalt");
}

Mehrere Bedingungen

if (temperatur > 25 && luftfeuchte > 70) {
    Serial.println("Warm und feucht");
}

Negation

if (!systemAktiv) {
    Serial.println("System deaktiviert");
}

Ternärer Operator

int ausgang = sensorAktiv ? HIGH : LOW;

digitalWrite(ledPin, ausgang);

Kurzform für einfache Entscheidungen. Für verschachtelte Logik wird sie rasch schlechter lesbar.

switch / case

Bei mehreren klar definierten Zuständen kann switch übersichtlicher als eine lange if / else if-Kette sein.

Grundstruktur

switch (modus) {

    case 0:
        Serial.println("Aus");
        break;

    case 1:
        Serial.println("Automatik");
        break;

    case 2:
        Serial.println("Manuell");
        break;

    default:
        Serial.println("Unbekannter Modus");
        break;
}

Warum break wichtig ist

Ohne break läuft die Ausführung in den nächsten case weiter. 

case 1:
    Serial.println("Eins");
    break;

Dieses sogenannte fall-through kann absichtlich genutzt werden, ist aber häufig schlicht ein Fehler.

Schleifen

for-Schleife

for (int i = 0; i < 10; i++) {
    Serial.println(i);
}

Aufbau: 

for (Start; Bedingung; Veränderung) {
    // Code
}

LED mehrfach blinken

for (int i = 0; i < 5; i++) {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(200);

    digitalWrite(LED_BUILTIN, LOW);
    delay(200);
}

while

int x = 0;

while (x < 10) {
    Serial.println(x);
    x++;
}

Wird ausgeführt, solange die Bedingung wahr ist.

Endlosschleife

while (true) {
    // läuft für immer
}
Auf einem Mikrocontroller ist eine versehentliche Endlosschleife besonders lästig: Der Rest des Programms bekommt schlicht nie wieder Gelegenheit, irgendetwas zu tun.

do ... while

int x = 0;

do {
    Serial.println(x);
    x++;
}
while (x < 5);

Der Block wird mindestens einmal ausgeführt, weil die Bedingung erst am Ende geprüft wird.

break

for (int i = 0; i < 100; i++) {

    if (digitalRead(buttonPin) == LOW) {
        break;
    }
}

Beendet die aktuelle Schleife vorzeitig.

continue

for (int i = 0; i < 10; i++) {

    if (i == 5) {
        continue;
    }

    Serial.println(i);
}

Überspringt den Rest des aktuellen Durchlaufs.

Funktionen

Funktionen teilen ein großes Programm in überschaubare, wiederverwendbare Einheiten. Sobald ein Sketch mehr als einige Dutzend Zeilen umfasst, werden sinnvoll benannte Funktionen zunehmend wertvoll.

Funktion ohne Rückgabewert

void ledAn() {
    digitalWrite(ledPin, HIGH);
}

void bedeutet, dass die Funktion keinen Wert zurückgibt.

Funktion mit Parameter

void setLed(bool zustand) {
    digitalWrite(ledPin, zustand ? HIGH : LOW);
}

Aufruf:

setLed(true);

Mehrere Parameter

void blinkLed(int pin, unsigned long dauer) {

    digitalWrite(pin, HIGH);
    delay(dauer);

    digitalWrite(pin, LOW);
    delay(dauer);
}

Rückgabewert

int liesSensor() {
    return analogRead(A0);
}

Verwendung:

int wert = liesSensor();

Berechnung auslagern

float celsiusZuFahrenheit(float celsius) {
    return celsius * 1.8 + 32.0;
}

Frühes return

void pruefeSensor() {

    if (!sensorAktiv) {
        return;
    }

    int wert = analogRead(A0);
    Serial.println(wert);
}

Das kann tiefe Verschachtelungen vermeiden und Funktionen leichter lesbar machen.

Parameter per Wert

void verdopple(int wert) {
    wert *= 2;
}

Die Funktion erhält eine Kopie. Die ursprüngliche Variable des Aufrufers wird nicht verändert.

Parameter per Referenz

void verdopple(int &wert) {
    wert *= 2;
}

int zahl = 10;
verdopple(zahl);

// zahl ist nun 20

Gültigkeitsbereiche von Variablen

Globale Variable

int zaehler = 0;

void setup() {
    zaehler++;
}

void loop() {
    Serial.println(zaehler);
}

Globale Variablen sind grundsätzlich im gesamten Programm verfügbar.

Lokale Variable

void loop() {
    int messwert = analogRead(A0);

    Serial.println(messwert);
}

messwert existiert nur innerhalb dieser Funktion.

Block-Scope

if (sensorAktiv) {
    int wert = analogRead(A0);
}

// wert ist hier nicht mehr sichtbar

static lokal

void test() {

    static int aufrufe = 0;

    aufrufe++;

    Serial.println(aufrufe);
}

Die Variable ist nur innerhalb der Funktion sichtbar, behält ihren Wert aber zwischen mehreren Funktionsaufrufen.

Arrays

Ein Array speichert mehrere Werte desselben Datentyps hintereinander. Besonders bei Messwerten, LEDs, Pin-Listen und Puffern sind Arrays unverzichtbar.

Array anlegen

int messwerte[5] = {
    10,
    20,
    30,
    40,
    50
};

Index beginnt bei 0

int werte[] = {10, 20, 30};

Serial.println(werte[0]); // 10
Serial.println(werte[1]); // 20
Serial.println(werte[2]); // 30
Das erste Element besitzt den Index 0. Diese kleine Eigenheit hat bereits Generationen von Programmierern zuverlässig um genau eins danebenliegen lassen.

Array verändern

werte[1] = 99;

Array durchlaufen

int werte[] = {10, 20, 30, 40};

for (int i = 0; i < 4; i++) {
    Serial.println(werte[i]);
}

Anzahl Elemente bestimmen

int werte[] = {10, 20, 30, 40};

int anzahl =
    sizeof(werte) / sizeof(werte[0]);

Damit muss die Array-Länge nicht nochmals als magische Zahl im Programm stehen.

Mehrere LEDs über Array

const int ledPins[] = {3, 5, 6, 9};

const int anzahl =
    sizeof(ledPins) / sizeof(ledPins[0]);

void setup() {

    for (int i = 0; i < anzahl; i++) {
        pinMode(ledPins[i], OUTPUT);
    }
}

Außerhalb des Arrays

int werte[3] = {1, 2, 3};

werte[5] = 20; // FEHLER

C++ prüft Array-Grenzen normalerweise nicht automatisch. Dadurch kann fremder Speicher überschrieben werden.

Solche Fehler sind besonders unangenehm: Das Programm kompiliert möglicherweise problemlos und benimmt sich anschließend wie ein Gerät mit Poltergeist.

Zeichen und Texte

Ein einzelnes Zeichen

char buchstabe = 'A';

Einzelne Zeichen verwenden einfache Anführungszeichen.

C-String

char text[] = "Hallo Arduino";

Klassische C-Strings bestehen aus einem Array von char-Werten und enden intern mit einem Nullzeichen \0.

Arduino String

String name = "Arduino";

String text =
    "Hallo " + name;

Die Arduino-Klasse String ist bequem und bietet zahlreiche Methoden.

String zusammensetzen

String ausgabe = "Temperatur: ";
ausgabe += temperatur;
ausgabe += " C";

Serial.println(ausgabe);

Nützliche String-Methoden

text.length();

text.startsWith("ABC");

text.endsWith("XYZ");

text.indexOf(':');

text.substring(0, 5);

text.toInt();

text.toFloat();

text.trim();

String und RAM

Auf kleinen AVR-Mikrocontrollern kann intensives dynamisches Erzeugen und Verändern von String-Objekten den knappen RAM ungünstig fragmentieren.

Für kleine Lernprojekte ist String oft völlig ausreichend. Für lang laufende oder speicherkritische Systeme lohnt es sich, C-Strings und statische Puffer zu verstehen.

Flash-String mit F()

Serial.println(
    F("Diese Zeichenkette bleibt im Flash")
);

Auf AVR-Arduinos kann das F()-Makro helfen, statische Textkonstanten nicht unnötig in den knappen SRAM zu kopieren.

enum, struct und Klassen

enum

enum Betriebsmodus {
    AUS,
    AUTOMATIK,
    MANUELL
};

Betriebsmodus modus = AUTOMATIK;

Ein enum gibt Zuständen aussagekräftige Namen.

enum class

enum class Zustand {
    AUS,
    BEREIT,
    AKTIV,
    FEHLER
};

Zustand zustand = Zustand::BEREIT;

enum class ist die modernere, stärker typisierte Variante.

struct

struct Messung {
    float temperatur;
    float luftfeuchte;
    unsigned long zeit;
};

Objekt erzeugen:

Messung aktuell;

aktuell.temperatur = 22.5;
aktuell.luftfeuchte = 51.3;
aktuell.zeit = millis();

Warum Strukturen nützlich sind

Zusammengehörige Daten werden als logische Einheit behandelt. 

struct SensorDaten {
    float temperatur;
    float druck;
    float feuchte;
    bool gueltig;
};

Das ist wesentlich sauberer als vier voneinander unabhängige globale Variablen.

Einfache Klasse

class Led {
public:

    Led(int pin)
        : _pin(pin) {
    }

    void begin() {
        pinMode(_pin, OUTPUT);
    }

    void an() {
        digitalWrite(_pin, HIGH);
    }

    void aus() {
        digitalWrite(_pin, LOW);
    }

private:

    int _pin;
};

Klasse verwenden

Led statusLed(13);

void setup() {
    statusLed.begin();
}

void loop() {
    statusLed.an();
}

Viele Arduino-Bibliotheken funktionieren genau nach diesem Prinzip: Ein Objekt repräsentiert ein Hardwaremodul.

Zeiger und Referenzen

Zeiger gehören zu den mächtigsten, aber auch fehleranfälligsten Eigenschaften von C und C++. Für einfache Arduino-Projekte braucht man sie selten direkt. Spätestens bei Bibliotheken, Arrays, Speicherpuffern und komplexeren Funktionen begegnen sie einem aber.

Adresse einer Variable

int wert = 42;

int *zeiger = &wert;

&wert bedeutet: Adresse der Variable wert.

Wert über Zeiger lesen

int wert = 42;
int *zeiger = &wert;

Serial.println(*zeiger);

*zeiger greift auf den Wert an der gespeicherten Adresse zu.

Referenz

int wert = 10;

int &referenz = wert;

referenz = 20;

// wert ist ebenfalls 20

Eine Referenz ist vereinfacht betrachtet ein zusätzlicher Name für dasselbe Objekt.

Wann Vorsicht geboten ist

  • ungültige Zeiger
  • nullptr
  • falsche Array-Grenzen
  • Zeiger auf nicht mehr existierende Variablen
  • manuelle Speicherverwaltung
Mikrocontroller bestrafen Speicherfehler gern ohne aussagekräftige Fehlermeldung. Statt „IndexError“ gibt es dann mitunter einfach Unsinn, Reset oder Schweigen.

Pins und Pin-Modi

pinMode()

pinMode(13, OUTPUT);
pinMode(2, INPUT);
pinMode(3, INPUT_PULLUP);

Damit wird festgelegt, welche Aufgabe ein digitaler Pin übernimmt.

OUTPUT

pinMode(ledPin, OUTPUT);

Der Mikrocontroller treibt den Pin aktiv auf einen elektrischen HIGH- oder LOW-Pegel.

INPUT

pinMode(sensorPin, INPUT);

Der Pin wird hochohmig und dient als Eingang.

INPUT_PULLUP

pinMode(buttonPin, INPUT_PULLUP);

Aktiviert einen internen Pull-up-Widerstand. Das ist besonders praktisch für Taster.

Floating Input

Ein unbeschalteter digitaler Eingang mit INPUT besitzt keinen klar definierten Pegel. Er kann auf elektrische Störungen reagieren. 

pinMode(buttonPin, INPUT);

Ohne Pull-up oder Pull-down kann das Messergebnis scheinbar zufällig zwischen HIGH und LOW wechseln.

Board-Spannung beachten

Nicht jeder Mikrocontroller arbeitet mit denselben Signalspannungen.

  • klassische Uno-/Nano-AVR-Systeme: häufig 5 V
  • viele ARM-, ESP- und RP2040-Systeme: 3,3 V
Vor dem Anschluss fremder Hardware immer Datenblatt und zulässige Logikpegel prüfen. „Der Stecker hat gepasst“ ist keine elektrische Spezifikation.

Digitale Ein- und Ausgänge

Digitalen Ausgang setzen

digitalWrite(ledPin, HIGH);

digitalWrite(ledPin, LOW);

Digitalen Eingang lesen

int zustand =
    digitalRead(buttonPin);

Der Rückgabewert ist gewöhnlich HIGH oder LOW.

Blink-Beispiel

const int ledPin = LED_BUILTIN;

void setup() {
    pinMode(ledPin, OUTPUT);
}

void loop() {

    digitalWrite(ledPin, HIGH);
    delay(1000);

    digitalWrite(ledPin, LOW);
    delay(1000);
}

Taster steuert LED

const int buttonPin = 2;
const int ledPin = 13;

void setup() {

    pinMode(buttonPin, INPUT_PULLUP);
    pinMode(ledPin, OUTPUT);
}

void loop() {

    bool gedrueckt =
        digitalRead(buttonPin) == LOW;

    digitalWrite(
        ledPin,
        gedrueckt ? HIGH : LOW
    );
}

Warum LOW bei gedrücktem Taster?

Bei INPUT_PULLUP zieht der interne Widerstand den Eingang standardmäßig auf HIGH.

Der Taster wird typischerweise zwischen Eingang und GND angeschlossen. Beim Drücken wird der Eingang daher LOW. 

nicht gedrueckt → HIGH
gedrueckt       → LOW

Taster und Entprellung

Mechanische Kontakte schließen nicht perfekt. Beim Drücken eines Tasters kann der Kontakt innerhalb weniger Millisekunden mehrfach öffnen und schließen. Dieses Verhalten heißt Kontaktprellen.

Naiver Ansatz

if (digitalRead(buttonPin) == LOW) {
    zaehler++;
}

Das erhöht den Zähler nicht einmal, sondern möglicherweise hunderte oder tausende Male, solange der Taster gedrückt bleibt.

Flankenerkennung

bool letzterZustand = HIGH;

void loop() {

    bool aktuell =
        digitalRead(buttonPin);

    if (
        letzterZustand == HIGH &&
        aktuell == LOW
    ) {
        Serial.println("Gedrueckt");
    }

    letzterZustand = aktuell;
}

Damit wird nicht der Zustand selbst, sondern der Übergang von HIGH nach LOW erkannt.

Einfache Entprellzeit

const unsigned long debounceZeit = 30;

unsigned long letzteAenderung = 0;
bool stabilerZustand = HIGH;
bool letzterMesswert = HIGH;

void loop() {

    bool messwert =
        digitalRead(buttonPin);

    if (messwert != letzterMesswert) {

        letzteAenderung = millis();
        letzterMesswert = messwert;
    }

    if (
        millis() - letzteAenderung
        >= debounceZeit
    ) {
        stabilerZustand = messwert;
    }
}

Analoge Eingänge

Digitale Eingänge unterscheiden lediglich HIGH und LOW. Ein Analog-Digital-Wandler – ADC – misst hingegen einen Spannungswert und wandelt ihn in eine Zahl um.

analogRead()

int wert = analogRead(A0);

Auf klassischen 10-Bit-AVR-Arduinos liegt das Ergebnis typischerweise zwischen: 

0 ... 1023

Andere Mikrocontroller können andere ADC-Auflösungen verwenden.

Spannung berechnen

int adc = analogRead(A0);

float spannung =
    adc * (5.0 / 1023.0);

Dieses Beispiel setzt einen 10-Bit-ADC und eine Referenzspannung von 5 V voraus.

Niemals blind 5 V in die Formel schreiben, wenn das konkrete Board mit einer anderen Referenz arbeitet.

Potentiometer auslesen

void setup() {
    Serial.begin(115200);
}

void loop() {

    int wert = analogRead(A0);

    Serial.println(wert);

    delay(100);
}

map()

int sensor = analogRead(A0);

int prozent =
    map(sensor, 0, 1023, 0, 100);

Skaliert einen Wertebereich auf einen anderen.

map() arbeitet ganzzahlig

Die klassische Arduino-Funktion map() verwendet Ganzzahlarithmetik.

Für präzise Fließkommaberechnungen sollte man daher selbst rechnen. 

float prozent =
    sensor / 1023.0 * 100.0;

constrain()

wert =
    constrain(wert, 0, 100);

Begrenzt den Wert auf den angegebenen Bereich.

Messwerte mitteln

long summe = 0;

for (int i = 0; i < 10; i++) {
    summe += analogRead(A0);
}

float mittelwert =
    summe / 10.0;

Mehrere Messungen zu mitteln kann Rauschen reduzieren.

PWM-Ausgänge

Viele Mikrocontroller besitzen nicht auf jedem Pin einen echten analogen Spannungsausgang. Stattdessen wird häufig Pulsweitenmodulation – PWM verwendet.

analogWrite()

analogWrite(ledPin, 128);

Auf klassischen Arduino-Boards wird häufig ein Wertebereich von 0 bis 255 verwendet.

PWM ist meist keine echte Analogspannung

0   → 0 % Tastgrad
128 → ungefähr 50 %
255 → 100 %

Der Ausgang schaltet sehr schnell zwischen LOW und HIGH. Das Verhältnis zwischen Ein- und Ausschaltzeit bestimmt den Mittelwert.

LED dimmen

for (int helligkeit = 0;
     helligkeit <= 255;
     helligkeit++) {

    analogWrite(
        ledPin,
        helligkeit
    );

    delay(5);
}

Sensorwert auf PWM abbilden

int sensor =
    analogRead(A0);

int pwm =
    map(sensor, 0, 1023, 0, 255);

analogWrite(ledPin, pwm);

Nicht jeder Pin kann PWM

Welche Pins PWM unterstützen, ist vom Board abhängig. Bei klassischen Arduino-Boards sind PWM-Pins häufig mit einem ~-Symbol markiert.

Echter DAC

Einige Mikrocontroller besitzen echte Digital-Analog-Wandler. Dann kann tatsächlich eine variable Ausgangsspannung erzeugt werden.

Ob und wie das funktioniert, hängt vom jeweiligen Board ab.

Zeitsteuerung

delay()

delay(1000);

Wartet ungefähr 1000 Millisekunden.

Problem mit delay()

digitalWrite(ledPin, HIGH);

delay(10000);

digitalWrite(ledPin, LOW);

Während dieser zehn Sekunden kann der Programmablauf innerhalb dieses Threads keine anderen Aufgaben erledigen.

Sensoren, Taster und Kommunikation werden dadurch möglicherweise erst verspätet behandelt.

millis()

unsigned long jetzt =
    millis();

Liefert die verstrichene Zeit seit dem Programmstart in Millisekunden.

Nicht-blockierende Zeitsteuerung

const int ledPin = LED_BUILTIN;

const unsigned long interval = 1000;

unsigned long letzteZeit = 0;

bool ledStatus = false;

void setup() {

    pinMode(ledPin, OUTPUT);
}

void loop() {

    unsigned long jetzt = millis();

    if (
        jetzt - letzteZeit
        >= interval
    ) {

        letzteZeit = jetzt;

        ledStatus = !ledStatus;

        digitalWrite(
            ledPin,
            ledStatus
        );
    }
}

Warum diese Schreibweise?

if (jetzt - letzteZeit >= interval)

Diese Differenzbildung funktioniert auch dann korrekt, wenn der vorzeichenlose Zeitwert von millis() irgendwann überläuft.

Weniger robust wäre: 

if (jetzt >= letzteZeit + interval)

micros()

unsigned long start =
    micros();

Liefert eine Zeitbasis in Mikrosekunden. Die tatsächliche Auflösung ist hardwareabhängig.

delayMicroseconds()

delayMicroseconds(10);

Für kurze, präzisere Verzögerungen im Mikrosekundenbereich.

Mehrere Intervalle gleichzeitig

unsigned long letzteMessung = 0;
unsigned long letzteAnzeige = 0;

void loop() {

    unsigned long jetzt = millis();

    if (
        jetzt - letzteMessung
        >= 1000
    ) {
        letzteMessung = jetzt;
        sensorLesen();
    }

    if (
        jetzt - letzteAnzeige
        >= 5000
    ) {
        letzteAnzeige = jetzt;
        displayAktualisieren();
    }
}

Genau hier beginnt Arduino-Programmierung interessant zu werden: Mehrere Aufgaben laufen scheinbar gleichzeitig, obwohl sie nacheinander abgearbeitet werden.

Zustandsautomaten

Für größere Programme ist ein Zustandsautomat (Finite State Machine) oft wesentlich besser als eine Landschaft aus verschachtelten if-Blöcken und delay()-Aufrufen.

Zustände definieren

enum class Zustand {
    BEREIT,
    MESSEN,
    WARTEN,
    FEHLER
};

Zustand zustand =
    Zustand::BEREIT;

Zustände bearbeiten

switch (zustand) {

    case Zustand::BEREIT:

        if (startBedingung()) {
            zustand = Zustand::MESSEN;
        }

        break;


    case Zustand::MESSEN:

        messungDurchfuehren();

        zustand = Zustand::WARTEN;

        break;


    case Zustand::WARTEN:

        if (wartezeitVorbei()) {
            zustand = Zustand::BEREIT;
        }

        break;


    case Zustand::FEHLER:

        fehlerAnzeigen();

        break;
}

Vorteile

  • klar definierte Systemzustände
  • weniger Blockierung
  • leichter zu debuggen
  • leichter erweiterbar
  • zeitliche Abläufe werden nachvollziehbar

println()

I²C – Inter-Integrated Circuit

I²C ist ein serieller Bus, über den zahlreiche Sensoren, Displays, Echtzeituhren und andere Bausteine mit nur wenigen Leitungen kommunizieren können.

Typische Leitungen

  • SDA – Serial Data
  • SCL – Serial Clock
  • GND
  • gegebenenfalls Versorgungsspannung

Wire-Bibliothek

#include <Wire.h>

void setup() {
    Wire.begin();
}

void loop() {

}

I²C-Adressen

Geräte am selben Bus besitzen normalerweise unterschiedliche Adressen. 

0x27
0x3C
0x68
0x76

Die tatsächliche Adresse muss aus Dokumentation, Datenblatt oder per I²C-Scanner ermittelt werden.

Daten an Gerät senden

Wire.beginTransmission(0x40);

Wire.write(0x01);

Wire.endTransmission();

Daten anfordern

Wire.requestFrom(0x40, 2);

while (Wire.available()) {

    byte daten =
        Wire.read();
}

Typische I²C-Probleme

  • falsche Adresse
  • SDA und SCL vertauscht
  • fehlende gemeinsame Masse
  • falsche Versorgungsspannung
  • fehlende oder ungeeignete Pull-ups
  • zu lange Leitungen
  • inkompatible Logikpegel

SPI – Serial Peripheral Interface

SPI ist ein schneller serieller Kommunikationsbus und wird häufig für Displays, SD-Karten, Funkmodule, ADCs und andere Peripherie eingesetzt.

Typische SPI-Leitungen

  • SCK – Clock
  • MOSI – Controller → Peripherie
  • MISO – Peripherie → Controller
  • CS / SS – Chip Select

SPI starten

#include <SPI.h>

void setup() {
    SPI.begin();
}

Mehrere Geräte

SCK, MOSI und MISO können von mehreren Geräten gemeinsam verwendet werden. Jedes Gerät besitzt normalerweise eine eigene Chip-Select-Leitung.

I²C oder SPI?

I²C:

  • weniger Leitungen
  • Adressierung mehrerer Geräte
  • häufig für Sensoren

SPI:

  • meist schneller
  • mehr Leitungen
  • häufig für Displays und Speicher

Interrupts

Ein Interrupt unterbricht den normalen Programmablauf kurzfristig, sobald ein bestimmtes Ereignis auftritt. Dadurch muss das Programm einen schnellen Vorgang nicht permanent mit digitalRead() abfragen.

Interrupt einrichten

volatile bool ereignis = false;

void interruptFunktion() {
    ereignis = true;
}

void setup() {

    pinMode(2, INPUT_PULLUP);

    attachInterrupt(
        digitalPinToInterrupt(2),
        interruptFunktion,
        FALLING
    );
}

Mögliche Trigger

RISING
FALLING
CHANGE

Verfügbarkeit und zusätzliche Modi können vom Board abhängen.

volatile

volatile bool ereignis = false;

Variablen, die sowohl im normalen Programm als auch in einer Interrupt-Service-Routine verändert werden, müssen häufig als volatile gekennzeichnet werden.

Damit wird dem Compiler signalisiert, dass sich der Wert außerhalb des normalen Kontrollflusses ändern kann.

ISR möglichst kurz halten

void interruptFunktion() {
    ereignis = true;
}

Gute Interrupt-Routinen erledigen nur das absolut Nötige. Umfangreiche Verarbeitung gehört in loop().

Schlechtes ISR-Muster

void interruptFunktion() {

    // möglichst vermeiden:
    delay(1000);

    // ebenfalls problematisch:
    // lange Berechnungen

    // umfangreiche Kommunikation
}

Interrupt nur als Signal

volatile bool datenBereit = false;

void sensorInterrupt() {
    datenBereit = true;
}

void loop() {

    if (datenBereit) {

        datenBereit = false;

        sensorAuslesen();
    }
}

Dieses Muster ist meist wesentlich robuster als die vollständige Verarbeitung innerhalb der ISR.

Speicher verstehen

Mikrocontroller besitzen verschiedene Speicherbereiche. Besonders bei kleinen AVR-Arduinos ist RAM eine ausgesprochen endliche Ressource.

Flash

Enthält hauptsächlich den kompilierten Programmcode und konstante Daten.

Der Inhalt bleibt ohne Versorgungsspannung erhalten.

SRAM

Arbeitsspeicher für:

  • Variablen
  • Arrays
  • Stack
  • dynamische Objekte

Der Inhalt geht beim Ausschalten verloren.

EEPROM

Nichtflüchtiger Speicher für kleinere Datenmengen. 

#include <EEPROM.h>

EEPROM.write(0, 42);

byte wert =
    EEPROM.read(0);

EEPROM nicht endlos beschreiben

EEPROM-Speicherzellen besitzen nur eine begrenzte Anzahl zuverlässiger Schreibzyklen.

Deshalb nicht in jedem loop()-Durchlauf denselben Wert neu schreiben.

Stack

Lokale Variablen und Funktionsaufrufe benötigen typischerweise Stack-Speicher.

Sehr große lokale Arrays oder tiefe Rekursion sind auf kleinen Mikrocontrollern entsprechend riskant.

Heap

Dynamisch reservierter Speicher wird typischerweise aus dem Heap bezogen. 

int *wert = new int;

*wert = 42;

delete wert;
Dynamische Speicherverwaltung ist auf kleinen Mikrocontrollern häufig unnötig und kann zu Fragmentierung oder Speicherfehlern führen.

Große Arrays bewusst verwenden

int messwerte[1000];

Auf einem PC völlig banal. Auf einem kleinen Mikrocontroller kann ein solches Array bereits einen beträchtlichen Teil des verfügbaren RAM verbrauchen.

Speicher sparen

  • kleinstmöglichen sinnvollen Datentyp verwenden
  • unnötige globale Arrays vermeiden
  • statische Texte sparsam behandeln
  • dynamische Speicherallokation vermeiden, wenn unnötig
  • Daten kontinuierlich verarbeiten statt alles zu puffern

Bitoperationen

Bitoperationen wirken anfangs unnötig kryptisch, sind bei Mikrocontrollern jedoch ausgesprochen nützlich – etwa für Register, Flags, Kommunikationsprotokolle oder kompakte Zustandsvariablen.

Binärdarstellung

byte wert = 0b00101101;

Ein Byte besteht aus acht Bits.

Bitweises UND

byte a = 0b10101010;
byte b = 0b11110000;

byte c = a & b;

Bitweises ODER

byte c = a | b;

XOR

byte c = a ^ b;

Bitweises NICHT

byte c = ~a;

Bitverschiebung

byte wert = 1;

wert = wert << 3;

Die Bits werden drei Positionen nach links verschoben.

Arduino-Hilfsfunktionen

bitRead(wert, 3);

bitSet(wert, 3);

bitClear(wert, 3);

bitWrite(wert, 3, 1);

Flags speichern

const byte FLAG_SENSOR = 0b00000001;
const byte FLAG_WIFI   = 0b00000010;
const byte FLAG_ERROR  = 0b00000100;

byte status = 0;

status |= FLAG_SENSOR;

Mehrere boolesche Zustände können so platzsparend in einem einzigen Byte gespeichert werden.

Debugging

Bei Arduino-Projekten kann ein Fehler aus Software, Elektronik, Stromversorgung, Verkabelung, Kommunikationsprotokoll oder Timing entstehen. Deshalb ist systematisches Vorgehen besonders wichtig.

1. Minimalen Test aufbauen

Nicht sofort das gesamte Projekt debuggen. Zuerst prüfen, ob die problematische Komponente isoliert funktioniert. 

void setup() {
    Serial.begin(115200);
}

void loop() {

    Serial.println(
        analogRead(A0)
    );

    delay(500);
}

2. Zwischenwerte ausgeben

Serial.print("raw=");
Serial.println(raw);

Serial.print("spannung=");
Serial.println(spannung);

Serial.print("status=");
Serial.println(status);

3. Programmfluss markieren

Serial.println("A");

sensorInitialisieren();

Serial.println("B");

displayInitialisieren();

Serial.println("C");

Bleibt die Ausgabe bei B stehen, weißt du zumindest, zwischen welchen beiden Punkten das Problem liegt.

4. Hardware prüfen

  • Versorgungsspannung messen
  • GND-Verbindungen prüfen
  • Pinbelegung prüfen
  • Datenblatt konsultieren
  • Leitungen auf Unterbrechungen prüfen
  • Signalpegel kontrollieren

5. Eine Änderung nach der anderen

Wer gleichzeitig Bibliothek, Verdrahtung, Pinbelegung, Baudrate und Programmstruktur verändert, weiß anschließend nicht, welche Änderung geholfen oder geschadet hat.

Compilerfehler von Laufzeitfehlern unterscheiden

Compilerfehler:

Das Programm lässt sich gar nicht übersetzen.

Laufzeitfehler:

Das Programm wird übertragen, verhält sich aber falsch.

Hardwarefehler:

Der Code kann völlig korrekt sein, während die reale Schaltung nicht funktioniert.

Typische Fehler

Semikolon vergessen

int wert = 10

Serial.println(wert);

Korrekt:

int wert = 10;

= statt ==

if (wert = 5) {
    // falsch gemeint
}

Korrekt:

if (wert == 5) {
    // Vergleich
}

Falscher Pin-Modus

pinMode(ledPin, INPUT);

digitalWrite(
    ledPin,
    HIGH
);

Prüfe immer, ob Eingang und Ausgang tatsächlich passend konfiguriert sind.

Floating Input

pinMode(buttonPin, INPUT);

Ohne definierten Pull-up oder Pull-down kann der Eingang unvorhersehbare Werte liefern.

Falsche Baudrate

Serial.begin(115200);

Ist der Monitor beispielsweise auf 9600 Baud eingestellt, erscheint häufig unlesbarer Zeichensalat.

Integer-Division

float wert = 5 / 2;

// 2 statt 2.5

Korrekt:

float wert = 5.0 / 2.0;

Array-Grenzen überschreiten

int daten[5];

daten[5] = 42;

Die gültigen Indizes sind lediglich 0 bis 4.

delay() überall

delay(5000);

Einfache Beispiele funktionieren damit gut. Mehrere gleichzeitig zu behandelnde Aufgaben hingegen werden schnell träge.

Ungeeigneter Datentyp für millis()

int zeit = millis(); // problematisch

Besser:

unsigned long zeit =
    millis();

Zu viel Strom direkt aus GPIO

GPIO-Pins sind für Logiksignale und begrenzte Lasten vorgesehen. Leistungsstarke Verbraucher gehören nicht unmittelbar an einen Mikrocontroller-Pin.

Motoren, Relais, kräftige LEDs und ähnliche Verbraucher benötigen meist geeignete Treiberstufen.

Motor direkt anschließen

Motoren erzeugen Stromspitzen und induktive Spannungsspitzen. Üblicherweise werden Transistoren, MOSFETs oder Motortreiber sowie passende Schutzmaßnahmen verwendet.

Gemeinsame Masse vergessen

Werden zwei separat versorgte Schaltungen elektrisch miteinander verbunden, benötigen ihre Logiksignale in vielen Fällen eine gemeinsame Bezugsspannung über GND.

Sauberer Programmierstil

Keine magischen Zahlen

Schlecht:

if (analogRead(A0) > 742) {
    digitalWrite(7, HIGH);
}

Besser:

constexpr int sensorPin = A0;
constexpr int relayPin = 7;

constexpr int grenzwert = 742;

if (
    analogRead(sensorPin)
    > grenzwert
) {
    digitalWrite(
        relayPin,
        HIGH
    );
}

Funktionen klein halten

Eine Funktion sollte möglichst eine klar beschreibbare Aufgabe erledigen. 

sensorLesen();
datenVerarbeiten();
displayAktualisieren();
datenSpeichern();

Variablennamen sollen Bedeutung tragen

unsigned long
    letzteMessung = 0;

float
    aktuelleTemperatur = 0.0;

Das ist länger als x und y, aber dramatisch günstiger als archäologische Codeforschung drei Monate später.

Konfiguration zentralisieren

constexpr int SENSOR_PIN = A0;
constexpr int LED_PIN = 9;

constexpr unsigned long
    MESSINTERVALL = 1000;

Hardware und Logik trennen

float temperatur =
    temperaturLesen();

bool luefterSollAn =
    temperatur > 30.0;

luefterSetzen(
    luefterSollAn
);

Dadurch bleibt die eigentliche Entscheidungslogik leicht verständlich.

Nicht-blockierend denken

Statt: 

aktionA();
delay(5000);
aktionB();

besser einen zeit- oder zustandsgesteuerten Ablauf verwenden.

Fehlerzustände einplanen

if (!sensor.begin()) {

    Serial.println(
        "Sensor nicht gefunden"
    );

    sensorFehler = true;
}

Ein gutes Embedded-Programm geht nicht davon aus, dass jede angeschlossene Komponente bis ans Ende aller Tage kooperiert.

Komplettes Praxisbeispiel

Dieses Beispiel verbindet mehrere zentrale Konzepte: analoge Messung, Taster, LED, Zustandsänderung, nicht-blockierende Zeitsteuerung und serielle Ausgabe. 

/*
    Beispiel:
    Sensorwert regelmäßig einlesen,
    LED abhängig von Grenzwert steuern,
    Taster kann Automatik aktivieren/deaktivieren.

    Kein delay() erforderlich.
*/


constexpr int SENSOR_PIN = A0;
constexpr int LED_PIN = 9;
constexpr int BUTTON_PIN = 2;

constexpr int GRENZWERT = 600;

constexpr unsigned long
    MESSINTERVALL = 1000;

constexpr unsigned long
    DEBOUNCE_ZEIT = 30;


unsigned long letzteMessung = 0;
unsigned long letzteTasterAenderung = 0;

bool automatikAktiv = true;

bool letzterRohzustand = HIGH;
bool stabilerTasterzustand = HIGH;
bool letzterStabilerZustand = HIGH;


void setup() {

    Serial.begin(115200);

    pinMode(
        LED_PIN,
        OUTPUT
    );

    pinMode(
        BUTTON_PIN,
        INPUT_PULLUP
    );

    Serial.println(
        F("System gestartet.")
    );
}


void loop() {

    tasterAktualisieren();

    messungAktualisieren();
}


void tasterAktualisieren() {

    bool rohzustand =
        digitalRead(BUTTON_PIN);


    if (
        rohzustand
        != letzterRohzustand
    ) {

        letzteTasterAenderung =
            millis();

        letzterRohzustand =
            rohzustand;
    }


    if (
        millis()
        - letzteTasterAenderung
        >= DEBOUNCE_ZEIT
    ) {

        stabilerTasterzustand =
            rohzustand;
    }


    bool wurdeGedrueckt =

        letzterStabilerZustand
        == HIGH

        &&

        stabilerTasterzustand
        == LOW;


    if (wurdeGedrueckt) {

        automatikAktiv =
            !automatikAktiv;

        Serial.print(
            F("Automatik: ")
        );

        Serial.println(
            automatikAktiv
            ? F("AN")
            : F("AUS")
        );
    }


    letzterStabilerZustand =
        stabilerTasterzustand;
}


void messungAktualisieren() {

    unsigned long jetzt =
        millis();


    if (
        jetzt - letzteMessung
        < MESSINTERVALL
    ) {
        return;
    }


    letzteMessung =
        jetzt;


    int sensorWert =
        analogRead(SENSOR_PIN);


    Serial.print(
        F("Sensorwert: ")
    );

    Serial.println(
        sensorWert
    );


    if (!automatikAktiv) {

        digitalWrite(
            LED_PIN,
            LOW
        );

        return;
    }


    bool grenzwertUeberschritten =
        sensorWert > GRENZWERT;


    digitalWrite(
        LED_PIN,
        grenzwertUeberschritten
        ? HIGH
        : LOW
    );
}

Was dieses Beispiel demonstriert

  • Pin-Nummern und Konfiguration werden als constexpr festgelegt.
  • Der Taster verwendet INPUT_PULLUP.
  • Ein Tastendruck wird über eine Flanke erkannt.
  • Der Taster wird softwareseitig entprellt.
  • Die Sensorabfrage erfolgt nur einmal pro Sekunde.
  • Es wird kein blockierendes delay() benötigt.
  • Die einzelnen Aufgaben befinden sich in eigenen Funktionen.
  • Die Programmlogik ist von der eigentlichen Hardwareausgabe weitgehend getrennt.

Die wichtigsten Regeln für die Praxis

  1. Arduino ist C++. Wer die Sprache hinter dem Framework versteht, stößt wesentlich später an Grenzen.
  2. Verwende aussagekräftige Namen. temperaturSensor ist besser als x2.
  3. Verwende const oder constexpr für feste Werte.
  4. Vermeide magische Zahlen. Pin 7 sollte im Code eine Bedeutung besitzen und nicht geheimnisvoll als nackte Sieben auftauchen.
  5. Nutze INPUT_PULLUP für Taster, wenn es elektrisch passt.
  6. Verstehe die invertierte Logik von INPUT_PULLUP. Gedrückt bedeutet häufig LOW.
  7. Entprelle mechanische Taster.
  8. Verwende delay() bewusst und sparsam.
  9. Lerne früh das millis()-Muster. Es ist einer der wichtigsten Schritte von simplen Demonstrations-Sketchen zu robusten Programmen.
  10. Speichere Zeitwerte als unsigned long.
  11. Berechne Zeitdifferenzen durch Subtraktion.
  12. Berücksichtige Integer-Division.
  13. Beachte Wertebereiche und Überläufe.
  14. Verlasse niemals die Grenzen eines Arrays.
  15. Behalte den RAM-Verbrauch im Auge. Besonders auf kleinen AVR-Boards.
  16. Verwende dynamischen Speicher nur, wenn du weißt, warum du ihn brauchst.
  17. Halte Interrupt-Routinen kurz.
  18. Verschiebe umfangreiche Arbeit aus Interrupts in loop().
  19. Nutze Funktionen zur Strukturierung.
  20. Verwende Zustandsautomaten für komplexe Abläufe.
  21. Prüfe Sensoren zunächst mit einem Minimalprogramm.
  22. Nutze die Beispielprogramme einer Bibliothek.
  23. Vertraue nicht blind auf Pinbelegungen aus fremden Tutorials. Sie können für ein anderes Board geschrieben worden sein.
  24. Prüfe die zulässige Betriebsspannung.
  25. Prüfe die Logikpegel. 3,3 V und 5 V sind nicht automatisch kompatibel.
  26. Leistungsstarke Verbraucher gehören nicht direkt an GPIO-Pins.
  27. Nutze geeignete Transistoren, MOSFETs oder Treiberschaltungen.
  28. Bei induktiven Lasten Schutzbeschaltung berücksichtigen.
  29. Vergiss die gemeinsame Masse nicht.
  30. Nutze den Serial Monitor offensiv.
  31. Debugge systematisch. Erst Versorgung und Hardware, dann Kommunikation, dann Softwarelogik.
  32. Ändere beim Debuggen möglichst nur eine Sache gleichzeitig.
  33. Teile große Programme in Module.
  34. Kommentare sollen Entscheidungen erklären.
  35. Behandle Compilerwarnungen nicht als dekorative Prosa.
  36. Lies Datenblätter. Dort steht, was die Hardware tatsächlich kann – nicht, was ein zufälliger Blogbeitrag behauptet.
  37. Denke in Zuständen, Ereignissen und Zeitpunkten. Das ist der Kern guter Embedded-Software.
Merksatz: Ein gutes Arduino-Programm besteht nicht darin, möglichst viele Befehle in loop() zu werfen. Es besteht darin, Hardwarezustände zu erfassen, daraus klare Entscheidungen abzuleiten und die erforderlichen Reaktionen rechtzeitig, nachvollziehbar und ohne unnötige Blockierung auszuführen.
